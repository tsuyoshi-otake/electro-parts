# ADR-0025: Pimoroni は基準通貨 GBP の Shopify カタログを転送なしで読み、日本向けの商品ページにも GBP の記録を出す

状態: 採用 / 2026-11-03 / Issue #57 / userscript 0.7.0

[Pimoroni](https://shop.pimoroni.com/)(`pimoroni`、英国)を 6 店舗目として追加する。M5Stack と同じく Shopify のカタログ JSON を読み、handle を同一性にする(ADR-0014、ADR-0015、[M5Stack の対応仕様](../roadmap/m5stack-support.md))。この ADR は、M5Stack と違う点(通貨の証拠、閲覧者の地域による転送、日本向けの商品ページ)と、利用規約の扱いを決める。

## 背景と境界

調査日は 2026-11-03。日本から、プロジェクトの User-Agent で、2 秒間隔、転送を追わずに読んだ。

- **robots.txt** は `User-agent: *` に `Allow: /` で、禁止はカート・購入手続き・アカウント・管理画面だけ。
- **利用規約**(`/policies/terms-of-service`)の禁止事項に「spider, crawl, or scrape」がある。Shopify の雛形の文言で、`shop.m5stack.com` の規約にも同じ条項がある(M5Stack は #21 から収集していたが、この条項は記録していなかった)。スイッチサイエンスの規約にこの条項はない。利用者(このプロジェクトの持ち主)は 2026-11-03 に、M5Stack と同じ扱いで進めると決めた。読むのは公開の一括カタログだけで、商品名・型番・メーカー表記・価格・在庫の有無・掲載の有無という事実を記録する。規約の解釈のリスクは残る。
- **通貨**: `/meta.json` は基準通貨 `GBP` を返す。HTML のページは閲覧者の地域で市場別のコピーへ転送する。日本からはトップ `/` が `302` で `/en-jp` を指し、`/en-jp` のページは Shopify Markets が換算した円を出す(調査時のレートは 215.46)。M5Stack のようにトップの `Shopify.currency` を読んでも、転送先の市場の通貨になるので、基準通貨の証拠にならない。
- **カタログ**: ルートの `/products.json?limit=250&page=N` は転送されずに GBP の金額を返した。12 ページ(250 × 11 + 104)で 2,854 商品・3,789 バリエーション。
- **サイトマップ**: 索引はルートの商品サイトマップ 3 つと、市場別のコピー(`/en-eu/`、`/en-us/`、`/en-no/`、`/en-au/`、`/en-jp/` など)を並べる。コピーは同じ商品を指す。
- **商品ページ**: 日本から開くと `/en-jp/products/<handle>` になり、canonical もそのアドレスを指す。商品欄は `.product-page` のグリッド(左の列に `.media` と `.about`、右の列に `.purchase`)。1024px 未満では 1 列になり、DOM の順に並ぶ。店舗の CSS は色をすべて自前の CSS 変数から引き、ヘッダーは暗い配色で描かれている。
- **境界**: 共通コアに店舗名を書かない。拡張の権限は広げない(履歴の取得先は Pages のまま)。コンテンツスクリプトの対象サイトには `shop.pimoroni.com` が加わる。

## 決定

### 収集(`src/collectors/shopify`、`src/collectors/pimoroni`)

- M5Stack の収集器を、店舗の設定(`ShopifyStore`: 店舗 ID・表示名・オリジン・通貨・通貨の証拠)を受け取る共通の Shopify 収集器にした。M5Stack と Pimoroni はその設定を渡すだけ。M5Stack の出力は変えない(移行の前後で、同じ入力からの保存データ・正規化データ・要求の列・エラーが一致することを確認した)。
- **通貨の証拠は `/meta.json` の基準通貨**にする(`currencyEvidence: 'meta'`)。`GBP` でなければ、または JSON でなければ、その実行を不完全として止める。
- **転送を追わない**。Pimoroni の要求は `redirect: 'manual'` で送り、`3xx` はそのまま応答の状態として扱う。共通の取得器は `3xx` を再試行しない失敗として扱うので、実行は不完全で止まる(ADR-0004)。地域で転送されると、同じ handle に別の通貨の金額が返り得るため。M5Stack は従来どおり転送を追う。
- **ルートの商品サイトマップだけを読む**(`/sitemap_products_<n>.xml`)。市場別のコピーは読まない。全件の照合(サイトマップの商品がカタログに全部あること)、重複・価格の書式・ページ数の上限の検査は M5Stack と同じ。
- 1 回の実行は 17 要求(`meta.json` 1、索引 1、商品サイトマップ 3、カタログ 12)。間隔 1.5 秒 + ジッタ 0.75 秒、要求数の上限 100、ページ数の上限 40。観測頻度は他店と同じ 2 日に 1 回(`config/pimoroni.json`)。

### 正規化(`src/adapters/shopify`、`src/adapters/pimoroni`)

- M5Stack と同じ写像を共通にした。handle が同一性(`h-` で始まる `pageKey`)、バリエーションごとのオファー、ペンスの整数、`compare_at_price` は別の価格基準、在庫は数量なし(`not_exposed`)。
- **GBP のまま記録する**。日本向けの円の表示は記録しない(Shopify Markets の換算で、レートも店舗の設定次第のため)。
- 税区分は「不明」(`unknown`)。`taxable` は税込・税抜の証拠にならない(M5Stack と同じ)。英国の VAT・送料・関税を含むかは記録しない。
- **GBP の円の参考値は、USD の応答から求めたクロスレートで添える**(#61)。為替レートの取得は USD の 1 URL だけ(ADR-0022)のまま、同じ応答の `JPY ÷ GBP` を使う。取得先・通信回数・権限は増えない。詳細は ADR-0022 の 0.7.0 追記。
- 店舗別の記録価格では、円以外の店舗として円の店舗の後ろに並ぶ(0.6.9)。

### 商品ページ(`userscript/adapters/pimoroni.ts`)

- パネルを出すのはルート(`/products/<handle>`)と日本向け(`/en-jp/products/<handle>`)の商品ページ。`/collections/<コレクション>/products/<handle>` も同じ商品として扱う。canonical が同じオリジン・同じ handle を指すときだけ、その商品とみなす。他の市場のコピー(`/en-eu/`、`/en-us/` など)では出さない。
- 日本向けのページでもパネルは GBP の記録を出す。ページの円の表示とは別の値になる。パネルの円の参考値も ExchangeRate-API のレートによるもので、店舗の換算(Shopify Markets)の円とは一致しない。
- パネルは `.about`(商品説明)の前に、`grid-column: 1` で置く。広い画面では左の列の商品画像の下、1024px 未満では購入欄の下になる(M5Stack と同じ位置づけ)。`.about` がなければ購入欄の後ろに置く。
- **ダークは店舗の CSS 変数を書き換えて掛ける**。要素ごとに色を上書きしない。背景は `#3e3e3e`、箱は `#343434`。ヘッダーは店舗の配色に戻す(スイッチサイエンス・M5Stack と同じ方針)。画像にフィルターを足さない。
- 動作するページはルートと `/en-jp` のトップ・コレクション・検索・固定ページ・ブログ・商品。カート・購入手続き・アカウントのページでは動作しない。

## 理由

基準通貨 GBP は店舗が一括カタログで返す値で、閲覧者の場所に左右されない。日本向けの円は換算の結果で、レートや丸めは店舗の設定で変わる。履歴として比べ続けられるのは GBP の方。

転送を追うと、どの市場の金額を記録したかが応答から分からなくなる。止めれば、その回の Pimoroni の記録は残らないが、別の通貨の金額を GBP として記録することはない。

M5Stack と Pimoroni は Shopify の同じ一括カタログを読む。違いは通貨とその証拠だけなので、収集・正規化は 1 つにして、店舗の設定で分けた。

## 結果

- 対応店舗は 6 つになる。Pimoroni の履歴は、この版のマージ後の初回観測から始まる。
- 0.7.0 では店舗間の対応表(ADR-0018)に入っていない。初回の観測の保存カタログから候補を探す。
- GitHub Actions の実行環境(日本以外)から `products.json` や `meta.json` が転送されると、Pimoroni の実行は毎回不完全で止まり、記録は始まらない。初回の実行で確かめる。
- Chrome ウェブストア版は、コンテンツスクリプトの対象サイトが増える。Chrome が更新時に利用者へ確認を求める可能性がある(未確認)。
- 店舗がカタログの形・基準通貨・転送の扱いを変えると、Pimoroni の実行は fail-closed で止まり、前回の公開データが残る(ADR-0005)。
- Pimoroni から申し入れがあれば、`STORES` から外して収集を止め、公開データから除く。
