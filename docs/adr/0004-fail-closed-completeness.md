# ADR-0004: 不完全なクロールは取り込まない(fail-closed)

- 状態: 採用(2026-09-06)
- 関連: `src/collectors/akizuki/crawl.ts`、`src/core/validation.ts`、`src/pipeline/run.ts`、ADR-0012

## 背景

一覧ページの一部が取れなかった(タイムアウト、メンテナンス、ページ構造の変化)スナップショットを取り込むと、取れなかった商品が「掲載なし」として記録され、後で「復活」したように見える。これは偽の履歴である。

## 決定

- Collector は run 全体の `complete` フラグを持ち、一覧の取得失敗、ページ数と件数の不一致(「N 件あります」と実際の抽出数の差)、パーサーの構造エラー、**サイトマップにあるのにどの一覧にも出なかった商品**(ADR-0012)があれば `complete: false` にする。
- validate 段階で `complete: false` のスナップショットは**拒否**し、取り込まない。CLI の `crawl` は終了コード 2 で知らせる。
- 部分的なカバレッジ(特定の一覧だけ)を取り込む仕組みは Phase 1 では作らない。`coverageId` は契約に含め、将来の部分クロールに備えるが、`coverageId` が前回と違う場合は健全性チェックが警告し、欠落統計を比較しない。

## 理由

欠けたデータを後から区別する方法がない。1 日分の観測を失う方が、偽の「掲載なし → 復活」を残すより安い。

## 結果

- サイトのメンテナンス日はデータが増えない。Actions summary に理由が出る。
- 秋月は分類ツリー 458 件とジャンルタグ 1,412 件、合わせて約 2,700 ページを歩く。1 ページ失敗しただけで run が無効になるので、丁寧な fetcher の再試行(最大 4 回)がその代償を下げる。
