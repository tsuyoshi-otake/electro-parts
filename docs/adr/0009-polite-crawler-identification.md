# ADR-0009: クローラーの識別と丁寧さ

- 状態: 採用(2026-09-06)
- 関連: `src/collectors/politeFetcher.ts`、`config/akizuki.json`

## 背景

対象は小規模な小売サイトで、クローラーは相手のリソースを使う。速さより「迷惑をかけない」「誰が何のためにアクセスしているか分かる」ことを優先する。

## 決定

- User-Agent は `electro-parts-price-history/0.1 (+https://github.com/tsuyoshi-otake/electro-parts; research)`。プロジェクト名、連絡先(リポジトリ URL)、目的を含める。ブラウザを偽装しない。
- 1 リクエストずつ、開始間隔 1.5 s + 0〜0.75 s のジッタ(既定)。並列なし。
- `Retry-After` を尊重(429 / 503)。408 / 429 / 5xx / ネットワークエラー / タイムアウトだけ指数バックオフで再試行(最大 4 回)。それ以外の 4xx は即時中止(サイトが拒否したら従う)。
- 1 run のリクエスト上限(既定 2,000)、ジャンルあたりのページ上限(200)。
- GET のみ、Cookie なし、セッション再利用なし。ログインや購入経路には触れない。
- 頻度は 1 日 1 回、日本時間の早朝(05:17)。
- アクセス制御(WAF、CAPTCHA、メンテナンスページ)を回避する仕組みは作らない。

## 理由

秋月の WAF は UA に `crawler` を含むリクエストを 403 で拒否した(2026-09-06 に確認)。これは「識別可能な UA を拒否する」のではなく特定語を弾いている挙動で、プロジェクト名の UA は受け入れられている。拒否されたら止まる、が唯一の正しい対応。

## 結果

- 200 ページで約 5〜8 分。予算(10 分)内。
- サイトから連絡があれば、UA の連絡先経由で対応できる。頻度の引き下げ・停止は config と schedule の変更だけで済む。
