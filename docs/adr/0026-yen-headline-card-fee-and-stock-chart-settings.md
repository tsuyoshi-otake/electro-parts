# ADR-0026: 現在の記録価格を円で見出しにし、カード手数料と在庫数グラフを設定モーダルで切り替える

状態: 採用 / 2026-11-03 / Issue #62・#63 / userscript・拡張 0.7.0

ADR-0022 では、USD・GBP の現在の記録価格の**下に**円の参考値を添えていた。オーナーの要望(2026-11-03)は 3 つある。

- グラフ下の店舗別価格を円で見たい。
- 円換算にカードの海外事務手数料を含めたい。カードの種類で選べるようにし、設定ボタンとモーダルで有効化する。既定は無効。
- 在庫数を表示している店舗では在庫数を記録し、グラフに出したい。表示は設定で切り替える。

この ADR は、円にする範囲、手数料の扱い、設定の保存、在庫数グラフ、店舗ごとの在庫数記録の可否を決める。記録データ(契約 v1)は変えない。

## 決定

### 円にするのは現在の価格だけ

- **見出しを円にするのは現在の記録価格だけ**。対象は次の 3 つ。
  - 閲覧中の商品。
  - 同一商品の店舗別の行。
  - 類似商品・候補カードの行。

  表示は `約 ￥868` を見出し(`.hero-value`)にし、その下に `記録価格 $5.50`(`.fx-recorded`)を置く。記録した $ / £ は常に見える。
- **変化幅・統計・グラフ・変更点の表は記録した通貨のまま**。変化幅は `記録価格 $5.50 +$0.50 (+10.0%)` のように、記録価格の行に付ける。理由は ADR-0022 と同じで、過去の記録には当時のレートが無いため。
- **並び順と「最安」は変えない**。円の店舗を先に並べる規則と、通貨が違う行に最安を付けない規則(ADR-0017・ADR-0022)は、円換算した値を読まない。
- **レートの注記はパネルに 1 つ**(`.fx-note`)。中身は次のとおり。
  - 「約 ￥」の意味。
  - 税・送料・関税を含まないこと。
  - 使った通貨ごとのレート、クロスレートの由来、提供元の更新日時。
  - 手数料を加算しているかどうか。
  - 出典リンク `Rates By Exchange Rate API`。
- **レートは、外貨の行が読み込まれたときにも取得する**。円の店舗のページに USD の公式ショップの行が出る場合もここに入る。取得先・保存項目・1 日 1 回の頻度管理は ADR-0022 のまま。
  - コントローラーは、閲覧中の商品と、読み込みが済んだ他店の商品の記録通貨を見る。`supports()` を満たす通貨ごとに 1 パネル 1 回だけ `get()` を呼ぶ。
  - 店舗名では分岐しない。
- **1 ページで USD の次に GBP を尋ねた場合**:
  - 最初の答えが 0.7.0 より前の保存項目(`cross` が無い)だったときだけ、クライアントがもう 1 回答えを作る(`crossAnswer`)。
  - リースとバックオフはそのまま効く。待機中なら GBP は出さず、通信もしない。

### カード手数料は設定で選び、既定は無効

- パネル見出しの「設定」ボタンで、ネイティブの `<dialog>` を `showModal()` で開く。これでトップレイヤー・背後の無効化・Escape・フォーカス復帰が付く。`showModal` の無いホスト(jsdom)では `open` 属性と同じ閉じ方に落とす。
- 設定を変えるたびに保存してパネルを再描画する。ダイアログは `settingsOpen` で開いたまま作り直し、フォーカスは `data-focus-key` で戻す。
- **手数料の既定は無効**。有効にすると、選んだカードの公表料率をレートに掛ける(`yenFromMinor(minor, rate, feePercent)` = 記録額 × レート × (1 + 料率/100) を円単位で四捨五入)。
  - 加算した値には「カード手数料 3.63%込み」と書く。
  - 注記にはカード名と料率を書く。
  - 自分で料率を入れる「その他」は 0〜10% だけを受け付け、範囲外は保存せずに入力欄の下にエラーを出す。
  - 料率が未入力の間は加算しない(推測で補わない)。
- **プリセットは発行会社の公式ページで確認した料率**(2026-11-03 確認、`CARD_FEE_RATES_CHECKED_ON`)。数日内に改定が告知されているカードは改定後の料率を採り、名前に明記する。

### 設定はこの端末だけに保存する

- 保存項目は `eph:prefs:v1` 1 つで、ホストの保存領域(`GM_setValue` / `chrome.storage.local`)に JSON で置く。中身は次の 3 つ。
  - `cardFee.enabled` / `cardId` / `customPercent`
  - `showStock`
- 送信はしない。通信先・権限・`@connect` も増えない。
- 読めない値は部分ごとに既定値へ戻す。廃止したカード ID は既定のカードに戻し、有効・無効はそのまま残す。
- テーマ(`eph:theme`)と同様に、書き込みは直列化し、遅い保存が後の操作を上書きしないようにする。
- 読み込みはテーマと並行させ、店舗ページの配色の適用を遅らせない。
- 保存に失敗しても、その画面では変更が効く(警告をログに出す)。

### 在庫数グラフ

- 価格グラフの下に、記録した表示在庫数の階段グラフ(`buildInventoryChart`)を描く。
  - 数が無い観測(`null`)では線を切る。
  - 各店舗は自分の最終観測で止める。
  - 点にフォーカスすると日時と数を確認できる。
- 店舗比較グラフでは、系列の ID・色・店舗の表示切替を価格グラフと共有する。
- 対象は `semantics !== 'not_exposed'` で、数が 1 つ以上ある offer だけ。判定は「最新の在庫表示」の表示在庫数と同じ関数(`shownQuantities`)で行う。
- 見出しは「表示在庫数の推移（店舗が表示した数。実在庫を保証しません）」とする。
  - 2026-11-04 改訂(0.7.5、[ADR-0027](0027-stock-counts-from-product-pages.md)): 見出しは「在庫数の推移（店舗のページが示す数。実在庫を保証しません）」、「最新の在庫表示」は「在庫数 N」。店舗の上限表示に達した数は「100+」と表示する。
- 設定の「在庫数の推移をグラフに表示」で切り替える。既定は表示。

### 在庫数の記録は、取得済みのデータに数がある店舗だけ

2026-11-03 の調査では、リポジトリのコード・fixture・文書を読んだ。ライブサイトへのアクセスはしていない。

| 店舗 | 店舗が数を表示するか | 今の取得元に数があるか | 判断 |
|---|---|---|---|
| 秋月電子通商 | する(「通販購入可能数」) | ある(一覧 HTML) | 記録済み(`site_reported`)。仕様表レイアウトの一覧では数が無く `null` |
| Raspberry Pi Shop by KSY | する(在庫数) | ある(一覧 JSON の `stock`) | 記録済み(`site_reported`) |
| スイッチサイエンス | 商品ページでする(「在庫数: 9」「100+」) | ない(カタログ JSON は `available` のみ) | 記録しない。取るには約 1 万商品ページ・4〜6.5 時間が必要で、240 分のジョブ上限を超える。ADR-0014 の「HTML で補わない」決定とも衝突する |
| M5Stack 公式 | 商品ページで段階表示(「10+ In Stock」)。正確な数はマークアップの属性だけ | ない | 記録しない。664 商品ページの取得は、オーナーが 2026-11-03 に許可した「公開カタログの一括取得」の範囲を超え、規約のクロール条項にも当たる |
| せんごくネット通販 | しない(欠品表示と店舗名だけ、ADR-0024) | ない | 記録しない(`not_exposed` のまま) |
| Pimoroni | 未確定(スクリプトで描かれ、保存ページに無い) | ない | 記録しない。商品ページは日本向けへの転送になり、ADR-0025 は転送で止める |

- **商品ページを 1 件ずつ取得して数を記録することは、この ADR では決めない**。店舗の負荷、ジョブ時間、規約の判断が要るため、オーナーの判断とし、決まったら店舗ごとに ADR を足す。
  - 2026-11-04 改訂: オーナーはスイッチサイエンスと M5Stack 公式の数を記録すると決めた。読む範囲・負荷の上限・規約の判断は [ADR-0027](0027-stock-counts-from-product-pages.md)。上の表のこの 2 店舗の「判断」は 2026-11-03 時点のもの。
- 数を記録している店舗が増えれば、グラフは契約を変えずにそのまま描く。

## 理由

- 見出しだけを円にすると、外貨の店舗を円の店舗と同じ単位で読める。一方で、記録した通貨・変化幅・統計を残すので、観測していない値を観測値のように見せない。
- 手数料をカード単位の公表料率にしたのは、ブランド単位の料率だけでは発行会社ごとの違い(1.6%〜4.5%)を表せないため。既定を無効にしたのは、カードを使わない支払いもあり、どの料率も全員には当てはまらないため。
- 設定をモーダルにしたのは、パネル本体を増やさずに、まれにしか変えない選択をまとめるため。ネイティブの `<dialog>` は、フォーカスの閉じ込めと Escape を自前で書かずに済む。
- 在庫数の記録を広げないのは、取得済みのデータに数が無い店舗では、1 商品 1 リクエストの追加取得が必要になるため。ADR-0009・ADR-0016 の丁寧さと、ジョブの時間上限を優先した。

## 結果

- 円の店舗のページでも、外貨の行があると為替の取得が起き得る(1 ブラウザー 1 日 1 回のまま)。`public/privacy.html` と `docs/chrome-web-store-listing.md` に、取得の条件と新しい保存項目を書いた。
- 円の見出しは参考値で、手数料を含めても実際の請求額とは一致しない。注記とモーダルにそう書いた。
- カードの料率は変わり得る。`CARD_FEE_PRESETS` と `CARD_FEE_RATES_CHECKED_ON` を、改定の告知に合わせて更新する必要がある。
