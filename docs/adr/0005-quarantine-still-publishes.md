# ADR-0005: 隔離されたスナップショットでも公開は続ける

- 状態: 採用(2026-09-06)
- 関連: `src/core/sanity.ts`、`src/pipeline/run.ts`、`rejected_runs` テーブル

## 背景

完全に見えるスナップショットでも内容が壊れていることがある(サイト側の一時的な価格表示エラー、カテゴリの大規模移動、通貨表示の変更)。取り込めば履歴を汚染する。一方で、隔離のたびに公開を止めると、ユーザースクリプトは古い `datasetVersion` のまま、運用者は隔離が起きたことに気付きにくい。

## 決定

- 前回受理したスナップショットとの比較で、件数の 20 % 超の減少、既知商品の 20 % 超の消失、共通商品の 30 % 超の主価格変更、50 % 超の価格不明を検出したら**隔離**する(しきい値は「超」であり、ちょうど 20 % は通す)。
- 隔離は `rejected_runs` に理由(コード、指標)付きで記録し、履歴の系列には触れない。
- その上で**パイプラインは生成・最終化・公開まで進む**。公開されるデータは前回と同じ履歴だが、状態 DB には隔離の記録が増え、manifest の `generatedAt` が更新される。終了コードは 3 で、Actions には warning が出る。
- しきい値は `config/<store>.json` の `sanity` で調整できる。

## 理由

- 隔離の記録が公開状態に含まれると、次回 run はそれを前回状態として取得し、「連続して隔離されている」ことを判断材料にできる。
- 公開を止めないので、ユーザースクリプト側から見た可用性が下がらない。

## 結果

- ブートストラップ直後に隔離が起きると履歴が空なので、その場合だけ「公開するものがない」として `publishable: false` になる。
- 本当に価格が 30 % 以上変わった日(改定)は隔離される。運用者が確認してしきい値を一時的に上げるか、`--snapshot` で再取り込みする(ランブック参照)。
