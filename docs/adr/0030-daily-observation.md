# ADR-0030: 観測を全店舗で毎日行う

状態: 採用 / 2026-11-08 / Issue #82

関連: ADR-0016(観測頻度は店舗ごとに宣言する)、ADR-0027(商品ページから在庫数を読む)、ADR-0029(観測を止めた店舗)、`config/<store>.json`、`scripts/observed-stores.ts`、`src/core/observationDay.ts`、`src/publisher/generate.ts`

## 背景

- オーナーが 2026-11-08 に「1日に1回にしてよ全ストア」と指示した。直前に、スイッチサイエンスの商品で在庫数のグラフが出ない理由を調べ、観測が約 2 日に 1 回であることと、在庫数は 4 組に分けて読むため 1 商品の更新が約 8 日に 1 回であることが原因と分かった(欠陥ではなく、ADR-0027 の設計どおり)。
- 変更前は、workflow が毎日 05:00 JST に起動し、`schedule` ジョブ(`scripts/observation-schedule.ts`)が 2026-09-11 起点の隔日だけ `crawl` を通していた。観測する店舗の周期は `every_two_days` で、在庫数の組は 2 日で 1 つ進む番号(`observationRound`)で選んでいた。

## 決定

1. 観測している 5 店舗(秋月電子通商、スイッチサイエンス、M5Stack 公式、せんごく、Pimoroni)の `observation.cadence` を `daily` にする。KSY は `stopped` のまま(ADR-0029)。
2. 隔日を判定する仕組みを消す: `schedule` ジョブ、`scripts/observation-schedule.ts`、`observationDue`、`observationRound`。cron は `0 20 * * *` のままで、毎回の起動が観測日になる。環境変数は `EVERY_TWO_DAYS_CRON` から `DAILY_CRON` に変える。`every_two_days` の名前は残さない(使わない周期を残すと、設定と注意書きが食い違う種類のずれを許す)。
3. 在庫数ページの組は、観測日の番号(`observationDayCount`)を `shards` で割った余りで選ぶ。`shards` は変えない。スイッチサイエンスの 1 商品の数は約 4 日に 1 回、M5Stack 公式は毎日更新される。
4. 観測間隔の表明は `SAMPLING` の表 1 つにまとめる(`src/publisher/generate.ts`)。`daily` は注意書きキーなし・`samplingIntervalDays: 1`、`weekly` と `monthly` は従来のキー、`stopped` は何も出さない。表は周期の型で網羅されるので、周期を足して表を忘れるとコンパイルが通らない。
5. 契約に新しい注意書きキーは足さない(ADR-0029 と同じ理由。旧版クライアントは未知のキーを拒否する)。ユーザースクリプトと拡張(0.7.7)は `samplingIntervalDays === 1` を「おおむね1日に1回」と表示する。`=== 2` の文言は、隔日の間に配信されたデータを読むために残す。

## 負荷

| | 変更前(隔日) | 変更後(毎日) |
|---|---|---|
| 1 run の内容 | 秋月 約 2,700 リクエスト・約 88 分、スイッチサイエンスのカタログと在庫ありの 1/4 ページ、M5Stack 公式の全商品ページ | 同じ |
| 1 run の長さ | 約 2 時間 55 分(2026-11-07 の run、run 42425487170) | 同じ。ジョブの上限 240 分に対して約 65 分の余裕 |
| 1 日あたりの観測量 | 平均して 1 run の半分 | 1 run ぶん(2 倍) |

各店舗へのアクセス間隔・ジッター・再試行上限・打ち切り条件は変えない。1 リクエストごとの負荷は同じで、来る頻度が 2 倍になる。run の長さが 240 分の上限に近づいたら、店舗を分けるより先に、スイッチサイエンスの `maxPages`/`maxMinutes` と秋月の所要時間を確認する。

## 影響

- 各店舗の `datasetVersion` は、周期が出力の入力に入っているので、最初の公開で 1 回だけ変わる。公開データの形(契約 v1)は変わらない。
- 0.7.6 以前のクライアントは `samplingIntervalDays: 1` を知らないか、正の整数として受け付けるので、データを読める。間隔の注意書きは、0.7.7 に更新するまで出ない。
- 切り替えの日だけ、在庫数の組が隔日の番号のときと連続しない。1 回読む組が前後でずれるだけで、読み残しはその後の回転で埋まる。
- 観測回数が 2 倍で増えるので、状態 DB(約 6 MB)と 90 日保存するスナップショットの量も増える。1 run あたりの量は変わらない。
- 「変化点の時刻」は、変化を初めて観測した時刻のままである。間隔が 1 日になるだけで、観測の間の変化は記録されないことは変わらない。

## 検討して採らなかったもの

- **隔日のまま、スイッチサイエンスの組を 2 つにする。** 在庫数の更新は約 4 日になるが、観測そのものは 2 日に 1 回のままで、依頼の「1日に1回」を満たさない。
- **`every_two_days` を残して `daily` を足す。** 使わない周期が残ると、設定・cron・注意書きのずれを許す(ADR-0016)。
- **新しい注意書きキー `sampling_interval_daily` を配信する。** 旧版が未知のキーを拒否して、パネルが全体として読み込めなくなる(ADR-0029)。クライアントの文言のキーとしてだけ持つ。
