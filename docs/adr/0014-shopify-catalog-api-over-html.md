# ADR-0014: Switch Science は HTML ではなく Shopify のカタログ JSON から読む

- 状態: 採用(2026-09-07)
- 関連: `src/collectors/switch-science/`、`src/adapters/switch-science/rawSchema.ts`、ADR-0004、ADR-0008、ADR-0009、ADR-0012

## 背景

Switch Science の店舗は Shopify である。同じカタログに 2 通りの入口がある。

- 一覧ページの HTML。秋月に対して採った方法(ADR-0008)と同じで、正規表現で読む。
- `/collections/<collection>/products.json?limit=250&page=N`。Shopify が公開ビューとしてそのまま返す JSON で、`limit` の上限は 250(それ以上を指定しても黙って 250 になる)。

実測した規模は 10,382 商品である。JSON なら 42 ページ、`sitemap.xml` の索引 1 + 商品サイトマップ 11 を足しても 1 回のクロールが約 54 リクエストで終わる。HTML 一覧を歩けば、同じ情報を得るのに桁が 2 つ違う。

HTML にはもう 1 つ費用がある。マークアップは店舗の都合で変わる。秋月では実際に変わることを前提に、保存済みページに対する回帰テストと sanity しきい値でそれを検出する設計にした(ADR-0008、ADR-0005)。同じ費用を、避けられる場所でまで払う理由はない。

## 決定

- 収集は `/collections/all/products.json` を `limit=250` で歩く。**短いページ(`limit` 未満)が返ったら終わり**、というのが停止条件である。
- 完全性の正解はサイトマップに置く(ADR-0012 の適用)。`sitemap.xml` の索引から `sitemap_products_*.xml` だけを読み、API が返さなかった商品を `uncovered` として数える。`maxUncoveredProducts` を超えたらエラーにして `complete: false` にする。ページ・コレクション・ブログのサイトマップは**読まない**。この収集器が集めない内容で、取りに行けば相手の負荷になるだけである。
- 生スナップショットには API の値をほぼそのまま入れる。価格は `priceRaw`(店舗が返した文字列)と `priceYen`(厳密に整数円に読めたときだけの数値)の両方を持つ。丸めない。
- 形が想定と違うページに当たったら、そこで**歩くのをやめる**。飛ばして先に進めば、それ以降の件数はすべて推測になる。エラーは「どのページで」を必ず含める。
- 商品ページの HTML は収集に使わない。ユーザースクリプトのページアダプターだけが DOM を読み、それも同一性の確認(canonical link)のためだけである。

## 理由

この API は「秘密の裏口」ではなく、ストアフロントが自分の表示に使っている公開ビューである。だから返ってくる値は、利用者がそのページで見る値と同じものであり、HTML から取り出そうとしていたものと一致する。取り出し方だけが安い。

一方で、これは**契約ではない**。Shopify の店舗設定で無効にできるし、仕様として保証されたものでもない。だから ①生の応答をスナップショットとして残し、②収集器は `StoreCollector` インターフェースの背後に隔離してある。API が閉じたら、HTML を読む収集器を同じ境界に差し替えるだけで、共通ドメインから先は 1 行も変わらない。

## 結果

- 1 回のクロールが約 54 リクエスト、`minIntervalMs: 1500` でも数分で終わる。月 1 回の観測(ADR-0013)に対して、相手サイトへの負荷は無視できる大きさになった。
- マークアップ変化による破損という失敗クラスが消えた。代わりに **JSON の形の変化**という失敗クラスが残るが、こちらは「`products` が配列でない」のように機械的に判定でき、当たれば `complete: false` として取り込みを拒否する(ADR-0004)。
- 一括カタログ API は在庫の**数**を返さない。返すのは `available` という真偽値だけである。したがって `StoreCapabilities` は `supportsInventoryQuantity: false` / `inventoryQuantitySemantics: 'not_exposed'` を宣言し、UI は在庫数の欄そのものを出さない(0 と表示するのではない。0 と非公開は違う)。**返ってこないものを商品ページの HTML から補いに行くことはしない**。それは 2 つの入口の値が食い違ったときに、どちらが正しいかを決める仕事を新しく作ることになる。
- 生スナップショットは 1 回あたり約 7.8 MB(gzip)。テストのフィクスチャはこれを 60 商品に切り出したもので、切り出しの手順と再生成方法は `tests/fixtures/switch-science/README.md` にある。
