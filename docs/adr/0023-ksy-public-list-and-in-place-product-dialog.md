# ADR-0023: Raspberry Pi Shop by KSY は公開一覧の JSON を offset で読み、ページ遷移のない商品ダイアログを追う

状態: 採用 / 2026-10-29 / Issue #32 / userscript 0.5.0

[Raspberry Pi Shop by KSY](https://raspberry-pi.ksyic.com/)(`ksy`)を 4 店舗目として追加する。この店舗は ColdFusion の 1 ページ構成で、商品一覧も商品詳細も同じページの中で JSON から描画する。この ADR は、何を**どこから**読み、**どこまでを**全件とみなし、商品ページの**どこに**パネルを出すかを決める。

## 背景と境界

調査日は 2026-10-29。

- **一覧の取得先**: 店舗の画面が使う `remote_proxy.cfc?method=process&returnFormat=json&argumentCollection=…`(`ev: product.list`)は、識別できる User-Agent を付けた**Cookie なしの GET** で JSON を返す。セッションやページ固有のトークンは要らない(ADR-0009 の範囲に収まる)。利用規約に自動取得を禁じる条項はなく、robots.txt もこのパスを禁止していない。
- **ページ送り**: `page` は黙って無視され、同じ先頭 50 件が返る。効くのは `offset` で、応答の `conditions.offset` に受け取った値が返る。`max` は 11〜59 だけ受け付け、範囲外は `failures` に検証メッセージが入る。
- **件数**: 応答の `size` が公開一覧の総数。登録日の昇順(`sort: 7, sortdesc: 0`)、`max: 50` で 16 回取得し、776 件が重複なく `size` と一致した。
- **各商品**: `id`、`name`、`make`、`model`、税込の整数 `price`、`tax`、`taxrate`、整数 `stock`(画面上の「在庫数」)、`onlist`、状態(`現行品` / `販売予定品` / `終了品`)。規約は全価格を税込と定める。`price` が `99999999` の商品は「価格未定」、`0` はシリーズ一覧用の項目。
- **数字だけの型番**: ColdFusion の JSON 直列化で数値として返る(例: `4910066630270`)。文字列に戻して保存するが、先頭のゼロなど元の表記は復元できない。
- **非公開の商品**: 一覧に出ない商品(`onlist: 0`)は ID を直接指定すると取れる。調査で ID を走査したところ、**個人名の入った顧客別の決済用商品**が含まれていた。走査結果は削除した。
- **商品ページ**: 一覧で商品を開くとダイアログ(`#detail`)に詳細を描き、アドレスは変えない(`history.replaceState`)。固定リンク `/main/index/pdp.id/<id>/pdp.open/<id>` から開いた場合も、同じダイアログに描く。
- **境界**: 共通コア(`src/core`、`src/db`、`src/publisher`、`src/pipeline`、`userscript/core`、`userscript/ui`)に店舗名を書かない。拡張の権限は広げない。

## 決定

### 収集(`src/collectors/ksy`)

- **公開一覧だけを読む**。ID を列挙・走査しない。応答の全商品が `onlist === 1` で、`conditions.onlist` が `1` であることを毎ページ確認し、外れたら失敗にする。テスト用の保存データにも非公開の商品を入れない。
- **`offset` で送り、`size` を全件の基準にする(fail-closed、ADR-0004)**。次のどれかで実行を不完全として止める。
  - 返ってきた `offset` が要求と違う。
  - 途中で `size` が変わる。
  - ページの件数が `min(pageSize, size − offset)` と違う。
  - 同じ ID が 2 回出る。
  - `failures` に検証メッセージが入る。
  - JSON でない応答が返る。
  - ページ数の上限(既定 40)に達する。
- 取得は `PoliteFetcher`(GET のみ・Cookie なし・間隔 1.5 秒 + ジッタ・`Retry-After` 尊重・要求数上限 100)。403 などの拒否では再試行しない。
- **観測頻度は他店と同じ 2 日に 1 回**(`config/ksy.json`、ADR-0016)。1 回の観測は 16 リクエスト程度。

### 正規化(`src/adapters/ksy`)

- 商品の同一性は店舗の商品番号(`id`)。`pageKey` と `externalProductId` に同じ値を使い、固定リンクを正規 URL にする。
- 価格は税込の円で記録する。`tax ≈ price − price / taxrate`(±1 円)を満たさない商品があれば、その実行を失敗にする(税抜に変わったことを黙って記録しない)。
- `99999999` と `0` は**価格なし**(`unavailable`)として記録し、金額にしない。価格なしの割合の上限は 15%(2026-10-29 時点で 776 件中 43 件、5.5%)。
- 在庫数は店舗が表示した数値(`site_reported`)。状態は `終了品` → 販売終了、在庫あり → 在庫あり、在庫 0 の `販売予定品` → 準備中、それ以外の在庫 0 → 在庫切れ。`現行品` 以外の状態名は `rawStatus` に残す。
- 型番は文字列にして前後の空白を除き、空なら記録しない。カテゴリは記録しない。

### 商品ページ(`userscript/adapters/ksy.ts`)

- **ページ遷移せずに商品が変わる画面のための、店舗名を含まない契約を足す**。`StorePageAdapter.watchPageKey(doc, onChange)` は省略可能で、表示中の商品が変わったときだけ新しい `pageKey`(商品が表示されていなければ `null`)を通知し、購読解除の関数を返す。
- コントローラーは通知に合わせて**パネルを 1 つだけ**表示する。前の商品のパネルは閉じ、閉じたパネルの読み込みと描画は止める(読み込みの途中で商品が変わっても、前の商品は表示しない)。同じ商品の通知では作り直さない。ページがパネルを取り除いた場合だけ作り直す。テーマの選択は次の商品のパネルに引き継ぐ。
- ダーク選択中にパネルがない間だけ、他店と同じく「ライトに戻す」を出す。パネルを表示したら取り下げる(パネルに自前のテーマ切替があり、ダイアログの上に重なるため)。パネルが閉じたら再び出す。
- KSY のアダプターは、ダイアログの商品番号 `#dt_id` と固定リンク `#dt_Permalink` が**同じ商品を指すときだけ**その商品を表示中とみなす。どちらかが空・不一致・別オリジンなら `null`。ダイアログが非表示(`display: none`)の間も `null` にする。店舗はダイアログを閉じても中身を消さないため、表示状態を見ないと閉じた商品のパネルが残る。
- パネルはダイアログ内の説明文 `#dt_Description` の直前に `clear: both` で置く(写真と購入欄の下)。
- 動作するページは `/`、`/?*`、`/main/index*`、`/news/*`、`/page/*`、`/forcustomer/*`。パネルを出すのは `/` と `/main/index*` のダイアログだけ。カート・購入手続き(`/transaction`)、会員登録(`/user`)、マイページ(`/manager`)、ログイン(`/main/login`)、問い合わせ(`/info`)では動作しない。
- ダーク表示では、ロゴ画像が白背景向けのヘッダーと、ダイアログの濃い赤のタイトル帯(白文字)を店舗の配色のまま残す。ヘッダー自体は透明で白い本文の上に乗っているだけなので、白を明示する。右列の枠見出し(`#panel-right .frame > h4` など)は店舗の CSS で白背景を持つため、ダークの面として塗り直す。

## 理由

商品詳細のページを 1 件ずつ取ると 776 回以上の要求になり、価格・在庫数・状態は一覧の JSON にすべて入っている。一覧の JSON は店舗の画面自身が使う公開の読み取りで、Cookie もトークンも要らない。

ID の走査は非公開の商品まで拾い、その中に個人名があった。公開一覧に限れば、店舗が利用者に見せている範囲を超えない。非公開になった商品は「一覧から消えた」(掲載なし)として記録され、それ以上を推測しない。

`page` が無視される実例があったため、応答に返る `offset` と `size` を毎ページ照合する。どちらも店舗自身の値で、件数の上限を手で決めずに全件を判定できる。

ページ遷移のない商品切替は店舗固有ではなく、ダイアログやタブで商品を切り替える店舗なら同じ形になる。コントローラーに店舗名を書かずに済むよう、「表示中の商品が変わった」という事実だけを契約にした。

## 結果

- 対応店舗は 4 つになる。KSY の履歴は、この版のマージ後の初回観測から始まる。それ以前の履歴はない。
- 一覧だけを開いている間(商品を開いていない間)とダイアログを閉じた後はパネルを出さない。その間ダーク選択中なら、他店と同じく左下に「ライトに戻す」を出す。
- 店舗が一覧の API・ページ送り・税込表示を変えると、その店舗の実行は fail-closed で止まり、前回の公開データが残る(ADR-0005)。
- 0.5.0 では KSY を店舗間の対応表(ADR-0018)に入れていなかった。0.5.1 で公開一覧の保存スナップショットから追加した(ADR-0018 の「0.5.1: Raspberry Pi Shop by KSYの追加」)。
