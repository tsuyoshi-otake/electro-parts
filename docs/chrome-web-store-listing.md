# Chrome ウェブストア 掲載情報(提出用の原本)

ダッシュボードの入力欄に貼る文言を、ここに 1 か所だけ持つ。提出は転記作業であって、その場で文章を考える作業にしない。
パッケージ側の要件(名前・説明の文字数、版番号、権限、リモートコード)は `tests/contract/chrome-web-store.test.ts` が機械的に検査しているので、
このファイルは**人が答える欄**だけを扱う。

- パッケージ: `npm run build:extension -- --zip dist/electronics-price-history-extension.zip`(公開済みの zip をそのまま出しても同じ)
- スクリーンショット: `npm run build:store-assets` → `dist/store/`
- プライバシーポリシー URL: <https://tsuyoshi-otake.github.io/electro-parts/privacy.html>(`public/privacy.html` が公開されたもの)
- 版: `userscript/version.ts` の `USERSCRIPT_VERSION`。**ストアは同じ版を 2 回受け付けない**ので、再提出のたびに上げる。

## 事前に必要なもの(人の作業)

1. Chrome ウェブストアのデベロッパー登録(初回のみ登録料 5 USD)。
2. Google アカウントの 2 段階認証を有効化(未設定だと公開できない)。
3. 連絡先メールアドレスの確認(ダッシュボードの「アカウント」→ 連絡先メール)。掲載ページに表示される。
4. 公開範囲は「公開」。有料機能・広告・アプリ内購入はなし。

### 説明(そのまま貼る)

```

・商品ページの購入エリアの下に、価格の推移グラフと観測値の一覧を表示します。
```

## プライバシータブ

### 単一用途の説明(そのまま貼る)

```
対応する電子部品通販サイトの商品ページで、その商品の価格・在庫・掲載状況の観測履歴を表示すること。この 1 つの用途以外の機能はありません。
```

### 権限の理由

| 項目 | 貼る文言 |
| --- | --- |
| `storage` | `取得した履歴データのキャッシュ(最大200商品のLRU)と、データ取得先URLの設定1項目を、利用者の端末内に保存するために使用します。他の用途では使用しません。` |
| ホスト権限 `https://tsuyoshi-otake.github.io/*` | `本拡張機能が表示する価格履歴データ(静的JSON)の取得先です。この1オリジンのみに限定しており、サービスワーカーがCookieを送らずに取得します。` |
| コンテンツスクリプトの対象サイト | `商品ページ上に履歴パネルを描画し、どの商品かを判定するために、対応する商品ページ(akizukidenshi.com/catalog/g/*、www.switch-science.com/products/*)でのみ実行します。ページの内容を外部に送信することはありません。` |
| リモートコードの使用 | **「いいえ、リモートコードは使用していません」**を選ぶ。実行されるコードはすべてパッケージ内にあり、難読化もしていない。 |

### データ使用の開示

Google の定義では「収集」は**利用者の端末外にデータを送信すること**を指す。本拡張機能はどのカテゴリのデータも送信しないので、
個人情報・健康情報・金融情報・認証情報・個人的な通信・位置情報・ウェブ閲覧履歴・ユーザーの操作・ウェブサイトのコンテンツの
**いずれも「収集していない」**と回答する。表示中の商品ページの URL と商品番号はブラウザ内でのみ使用し、送信も保存もしない。

3 つの証明にはすべてチェックを入れる(いずれも事実):

- 承認された用途以外で第三者にユーザーデータを販売・譲渡していない。
- アイテムの単一用途と無関係な目的でユーザーデータを使用・譲渡していない。
- 信用力の判定や融資目的でユーザーデータを使用・譲渡していない。

プライバシーポリシー URL 欄には <https://tsuyoshi-otake.github.io/electro-parts/privacy.html> を入れる。

## 提出と、落ちたときの読み方

1. `npm run build:extension -- --zip <出力先>` の zip をアップロードする(公開済みの zip と同じもの)。
2. 上の各欄を転記し、審査に提出する。初回は数日かかることがある。
3. 却下されたらメールに**理由の項番**(例: Blue Argon = 権限の過剰要求、Yellow Magnesium = 説明と機能の不一致)が入る。
   直すのは掲載情報かパッケージのどちらかで、判断そのものを議論しない。パッケージを直した場合は版を上げて再アップロードする。
4. 公開後は、ストア側で自動更新が配られる。**zip の手動導入(デベロッパーモード)を続けている利用者は自動更新されない**ので、
   ランディングページと README は両方の導線を残す。
