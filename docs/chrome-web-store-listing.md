# Chrome ウェブストア 掲載情報(提出用の原本)

ダッシュボードの入力欄に貼る文言を、ここに 1 か所だけ持つ。提出は転記作業であって、その場で文章を考える作業にしない。
パッケージ側の要件(名前・説明の文字数、版番号、権限、リモートコード)は `tests/contract/chrome-web-store.test.ts` が機械的に検査しているので、
このファイルは**人が答える欄**だけを扱う。

- パッケージ: `npm run build:extension -- --zip dist/electronics-price-history-extension.zip`(公開済みの zip をそのまま出しても同じ)
- 掲載画像: `npm run build:store-assets` → `dist/store/`(スクリーンショット 4 枚とプロモーション タイル 2 枚)。ショップアイコンは生成しない。パッケージ同梱の `dist/extension/icons/icon-128.png` をそのまま上げる。
- プライバシーポリシー URL: <https://tsuyoshi-otake.github.io/electro-parts/privacy.html>(`public/privacy.html` が公開されたもの)
- 版: `userscript/version.ts` の `USERSCRIPT_VERSION`。**ストアは同じ版を 2 回受け付けない**ので、再提出のたびに上げる。

## 事前に必要なもの(人の作業)

1. Chrome ウェブストアのデベロッパー登録(初回のみ登録料 5 USD)。
2. Google アカウントの 2 段階認証を有効化(未設定だと公開できない)。
3. 連絡先メールアドレスの確認(ダッシュボードの「アカウント」→ 連絡先メール)。掲載ページに表示される。
4. 公開範囲は「公開」。有料機能・広告・アプリ内購入はなし。
5. トレーダーの申告(「アカウント」→ 設定)。個人の非商用公開なので**非取引業者**を選ぶ。取引業者を選ぶと氏名・住所・電話番号・メールアドレスが掲載ページに公開される。

### データ使用の開示

Google の定義では「収集」は**利用者の端末外にデータを送信すること**を指す。本拡張機能はどのカテゴリのデータも送信しないので、
個人情報・健康情報・金融情報・認証情報・個人的な通信・位置情報・ウェブ閲覧履歴・ユーザーの操作・ウェブサイトのコンテンツの
**いずれも「収集していない」**と回答する。表示中の商品ページの URL と商品番号はブラウザ内でのみ使用し、送信も保存もしない。
為替レートの取得(`https://open.er-api.com/v6/latest/USD`)は商品・ページ・利用者を含まない固定 URL の読み取りで、
公開データの取得と同じく、利用者のデータを送信するものではない。ホスト権限も追加していない(取得先が CORS で公開読み取りを許可している)。

3 つの証明にはすべてチェックを入れる(いずれも事実):

- 承認された用途以外で第三者にユーザーデータを販売・譲渡していない。
- アイテムの単一用途と無関係な目的でユーザーデータを使用・譲渡していない。
- 信用力の判定や融資目的でユーザーデータを使用・譲渡していない。

プライバシーポリシー URL 欄には <https://tsuyoshi-otake.github.io/electro-parts/privacy.html> を入れる。

## 提出と、落ちたときの読み方

転記は `scripts/cws-dashboard.ts`(`npm run cws:dashboard -- <コマンド>`)で行い、**「審査のため送信」は人が押す**。スクリプトは送信と公開のボタンを押さない(押せるボタンを許可リストで限っている)。

この経路にしている理由: ダッシュボード(`chrome.google.com/webstore/*`)は拡張機能からのスクリプト実行とスクリーンショットを拒むので、Claude in Chrome では操作できない。また Chrome は既定のプロファイルでは `--remote-debugging-port` を無視する。そこで専用の空プロファイルの Chrome をデバッグポート付きで起動し、人がその窓でログインしてから CDP で接続する。

前提:

- Pages がその版をもう配っている(`@version` と zip の SHA256 を確認済み)。プライバシーポリシーが 404 だと審査に出せない。
- 出す zip は、CLAUDE.md の「Chrome Web Store 申請前のローカル確認」で実ページ確認を済ませた zip そのもの(公開済みの zip とバイト一致)。

手順:

1. `npm run cws:dashboard -- launch` で専用プロファイル(既定 `~/tmp/electro-cws/profile`、ポート 9333)の Chrome を開く。
2. **人がその窓でデベロッパー ダッシュボードにログインする。** ログインが終わるまで接続しない(パスワードは人が入れる)。
3. `npm run cws:dashboard -- status` でステータスと版を見る。Expect: 審査中の版がない(審査中なら新しい版は出せない)。
4. `npm run cws:dashboard -- upload <検証済みの zip>`。Expect: ドラフトの版が新しい版になる。アイテム名と概要は zip のマニフェストから入る。
5. `npm run cws:dashboard -- fill` で、説明・単一用途・storage の理由・ホスト権限の理由をこの文書から貼り、各タブの下書きを保存する。ホスト権限の欄はダッシュボードに 1 つしかないので、データ取得先の行とコンテンツスクリプトの行を空行でつないで入れる。
6. `npm run cws:dashboard -- check`。Expect: 4 欄すべて `same`(`fill` の最後にも同じ確認が走る)。
7. `npm run cws:dashboard -- blockers` で「送信できない理由」を読む。Expect: `no blockers`(問題がないとダッシュボードは「送信できない理由」を出さず、「審査のため送信」が押せる状態になる。0.6.1 で確認)、または「公開できません」の本文に問題が 1 件もない。ダイアログは Escape で閉じる。「OK」などの文言でボタンを押すと、非表示のダイアログのボタンまで押してしまう(0.5.1 ではこれで審査に送られた)。
8. **人が「審査のため送信」を押し**、審査通過後に自動で公開するかを選ぶ。初回は数日かかることがある。
9. `npm run cws:dashboard -- close`。その Chrome を閉じ、ログイン済みのプロファイルを削除する。

リモートコード「いいえ」、データ使用の 3 つの証明、プライバシーポリシー URL、販売地域は版をまたいで残るので、`fill` は触らない。変えたときは手で直し、この文書も直す。

却下されたらメールに**理由の項番**(例: Blue Argon = 権限の過剰要求、Yellow Magnesium = 説明と機能の不一致)が入る。
直すのは掲載情報かパッケージのどちらかで、判断そのものを議論しない。パッケージを直した場合は版を上げて再アップロードする。

公開後は、ストア側で自動更新が配られる。**zip の手動導入(デベロッパーモード)を続けている利用者は自動更新されない**ので、
ランディングページと README は両方の導線を残す。
