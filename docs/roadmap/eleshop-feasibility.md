2026-09-12。ユーザーの希望は指定商品だけではなく全商品対応。収集・公開・拡張機能への対応はまだ実装していない。

同日の後続指示により本対応を保留し、[M5Stack公式ショップ](m5stack-feasibility.md)へ対象変更。問い合わせ文案は未送信のまま保存する。

## 確認済みの取得元

- [robots.txt](https://eleshop.jp/robots.txt): 一般クライアント向けに `/shop/c/`、商品検索、カート、アカウントのパスをDisallow。カテゴリ・検索による巡回は採用しない。
- [公式サイトマップ索引](https://eleshop.jp/Sitemap_index.xml): HTTP 200。13個のgzipサイトマップを参照。索引の更新日時は2026-09-11。
- 13ファイルを全部取得し、`https://eleshop.jp/shop/g/g<商品コード>/` に一致するURLを重複除外した結果は **489,531件**。商品URLは10ファイルに分かれ、9ファイルが各50,000件、1ファイルが39,531件。
- 他の3ファイルはトップ1件、カテゴリ2,943件、ジャンル2,490件。サイトマップを読んだだけでカテゴリページを巡回したわけではない。
- これはサイトマップ掲載URL数であり、現在購入可能な商品数・価格取得成功数ではない。全商品ページの取得は未実施。
- 保存済みの商品サイトマップ全10ファイル・489,531エントリをオフラインで再検査。XML要素はurlset・url・locのみで、商品単位のlastmodは0件。価格・在庫も含まれず、索引の更新日時だけで更新商品を判定できない。
- サイトマップ掲載の `/shop/r/rZZ07A008/` はHTTP 404だった。ジャンル一覧の網羅性・取得可能性は未確認。

## 商品ページの初回サンプル

調査件数は1商品、メーカーはArduino、カテゴリはメインボードのみ。全商品のパーサー検証を済ませたものではない。

[N6U315 / Arduino Uno R4 Minima](https://eleshop.jp/shop/g/gN6U315/) をプロジェクト名・連絡先を明示するUser-Agentで取得し、HTTP 200とShift_JISのHTMLを確認した。

- 商品コード: `#spec_goods`。元型番: 見出し内のABX00080。メーカー: `#spec_maker_name`。
- 価格: `#spec_price`内の税込表示。注文受付単位も同じセル内にある。
- 在庫: `#spec_stock_msg`に数値と「現在庫数」。取寄・売切・販売終了等の別状態は追加検証が必要。
- 注文受付単位1だけで「本体1個」とは判定しない。セット商品・数量割引・取寄品の条件を別に扱う。
- 在庫・価格はこの取得時点の記録であり、現在値として固定しない。

## 運用設計上の課題

個別HTML取得は商品数Nに対してO(N)リクエスト。489,531件を1.5秒間隔で取得するだけでも734,296.5秒（約8.5日）。ジッター・遅い応答・再試行・停止時間は含まない下限で、既存の隔日全件更新には収まらない。

現在の公開workflowは共有SQLiteを店舗ごとに直列処理し、収集jobの上限は240分。長い全件巡回を店舗リストに足すだけでは動作しない。

ユーザーは2026-09-12に方式1（一括データ提供元の調査を先行）を選択した。本番収集は未有効化。

1. 全件価格・在庫を取得できる公式の一括データ・許可された一覧を調査する。カテゴリ・検索の禁止を回避する別URLの使用や高速並列化を解決策にしない。
2. 全商品を分割して順次更新する。再開可能な巡回状態、商品ごとの観測日時、取得失敗・途中停止の確定処理、既存店舗を止めない実行設計が必要。未取得の商品を掲載終了とみなさず、数日分の観測を単一時刻のスナップショットとして扱わない。公開ファイル数・容量も実測が必要。

調査の限界: 公開Web・検索索引・取得済みHTMLを対象とし、契約者専用機能や社内システムは調査していない。Web取得ツールでFAQ・問い合わせ本文はInternal Errorだったため、当該ページの検索索引と取得済み商品ページのリンクで補完した。旧ドメイン `eleshop.kyohritsu.com` の古いFAQにあるDB接続の説明は、現行APIの不存在を証明する根拠にしていない。取寄特集の検索索引も約7か月前なので現在の取扱件数の根拠にはしていない。

次の実行条件: [問い合わせ文案](eleshop-data-inquiry.md)で全件提供・差分・利用条件を確認する。提供形式と範囲が確定してから実装Issueと検証基準を作る。2日更新は希望条件であり達成済みではない。

既存店舗との違い: 秋月はカテゴリ・ジャンルの一覧HTMLを読み取り、サイトマップと網羅性を照合する（`src/collectors/akizuki/crawl.ts`）。スイッチサイエンスは公開の `/collections/<collection>/products.json` をページ分割で読み取り、サイトマップと照合する（`src/collectors/switch-science/catalog.ts`、`crawl.ts`）。本プロジェクト用に個別の一括データ提供契約を受けているという意味ではない。エレショップの問い合わせは、既存店舗で必須だった手続きではなく、全件取得の負荷と利用可能な取得元を解決するための候補である。
