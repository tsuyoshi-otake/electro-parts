## バリエーションと参考価格

公式のページ単位の型番は複数variantなら空になる。レビューで対象のoffer ID・SKU・variant名を固定し、対応先リンクに `variant` を含める。共通ページを持つLEDテープ等も長さごとの参照を保持する。対象offerが消えたりSKUが変わった場合、別variantの価格にフォールバックしない。公式側では履歴パネルで選択中のvariantに対応する関連商品だけを表示する。

USDの整数セント・税区分不明の記録をそのまま表示する。送料・関税・販売数量・付属品・書込サービス・為替は価格比較未承認。全店舗の記録観測時刻を表示し、現在価格・最安値とは呼ばない。

## 再現・更新

1. 初回の公式追加: `npm run matching:build -- --import-m5stack <complete-snapshot.json.gz>`。既存ソースがある場合は停止する。小売の保存行を更新しない。
   新しい完全スナップショットでの補完: `npm run matching:build -- --supplement akizuki=<file> --supplement switch-science=<file> --supplement m5stack=<file>`。`catalog.jsonl` はその場で書き換わる。報告の `keptPinnedWithChanges` を確認し、照合の根拠が変わった行があれば `git checkout data/matching/catalog.jsonl` で戻してから、その行だけ `--replace <storeId>/<pageKey>` を付けて再実行する。
2. `npm run matching:discover`。全店舗ペアを探索するが、レビューや本番表は変更しない。
3. 商品名・型番・仕様・構成と対象offerを組別に確認してレビューを記録する。古い指紋の一括追認は禁止。
4. `npm run matching:build` と `npm run matching:check`、関連テストを実行する。生成物の直接編集は禁止。
