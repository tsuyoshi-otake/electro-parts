- 秋月: 2026-09-06取得、8,677商品、2026-10-03補完4,130商品。SS: 2026-08-02取得、10,343商品、2026-10-03補完101商品（差し替え1を含む）。公式: 2026-09-12取得、664商品・706 variants、2026-10-03補完9商品（差し替え1を含む）。合計23,922行。
- 3資料の全行・全カテゴリを検索し、件数上限では打ち切っていない。公式追加分のメーカーはM5Stackで、ATOM・Stamp・Stick・Nano、センサ、通信、電源、基板、ケーブル、アクセサリ、衣類等も含む。`vendor` の `m5stack-store` / `M5Stack-Store` は公式資料内だけでM5Stackに正規化し元値を残す。
- `catalog.jsonl` の元データ取得時刻・元型番・メーカー情報・variantsを指紋に含め、`reviews.json` に組別の根拠・判定日・モデル・原判定を残す。タイトル差の確認に使った公式本文は、元JSONファイル名・SHA-256・URL・確認した内容も記録する。

- 主要メーカーごとの件数と未一致数は `coverage.json`。これは保存資料の検索範囲であり、小売資料取得後に増えた商品・全別名・本文だけの型番は未網羅。全件の現行ページ再確認ではない。

## バリエーションと参考価格

公式のページ単位の型番は複数variantなら空になる。レビューで対象のoffer ID・SKU・variant名を固定し、対応先リンクに `variant` を含める。共通ページを持つLEDテープ等も長さごとの参照を保持する。対象offerが消えたりSKUが変わった場合、別variantの価格にフォールバックしない。公式側では履歴パネルで選択中のvariantに対応する関連商品だけを表示する。

USDの整数セント・税区分不明の記録をそのまま表示する。送料・関税・販売数量・付属品・書込サービス・為替は価格比較未承認。全店舗の記録観測時刻を表示し、現在価格・最安値とは呼ばない。

## 再現・更新

1. 新しい店舗の初回追加: `npm run matching:build -- --import-store <storeId>=<complete-snapshot.json.gz>`（0.5.1で `--import-m5stack` から一般化。M5Stack公式は0.4.5、KSYは0.5.1で追加）。その店舗のソースが既にある場合は停止する。既存店舗の保存行を更新しない。
   新しい完全スナップショットでの補完: `npm run matching:build -- --supplement akizuki=<file> --supplement switch-science=<file> --supplement m5stack=<file>`。`catalog.jsonl` はその場で書き換わる。報告の `keptPinnedWithChanges` を確認し、照合の根拠が変わった行があれば `git checkout data/matching/catalog.jsonl` で戻してから、その行だけ `--replace <storeId>/<pageKey>` を付けて再実行する。
2. `npm run matching:discover`。全店舗ペアを探索するが、レビューや本番表は変更しない。
3. 商品名・型番・仕様・構成と対象offerを組別に確認してレビューを記録する。古い指紋の一括追認は禁止。
4. `npm run matching:build` と `npm run matching:check`、関連テストを実行する。生成物の直接編集は禁止。
