# Goal: stop observing KSY (site gone) while keeping its published history (#80)
Workdir: the repository root (branch fix/stop-ksy-observation, uncommitted changes plus the new file scripts/observed-stores.ts)

Network rule for the verifier: never run the pipeline or `crawl` against a live store. The only CLI runs allowed are the ones written below (they stop before any network access, or run the selection script, which reads local config files only).

## Criteria

- C1: KSY is declared stopped, and the config parser accepts exactly the four cadences. Verify: read `config/ksy.json` and `cadence()` in `src/pipeline/config.ts`. Expect: `"cadence": "stopped"`; the parser accepts `every_two_days`, `weekly`, `monthly`, `stopped`, defaults to `monthly` when absent, and throws for anything else; the other five configs still declare `every_two_days`.
- C2: No run observes a stopped store. Verify: read `scripts/observed-stores.ts`, the "Run the pipeline for every store" step in `.github/workflows/crawl-publish.yml`, and run `npx vitest run tests/integration/observation-cadence.test.ts`. Expect: a schedule observes only `every_two_days` stores; a manual run with empty `stores` observes every store except stopped ones; naming a stopped or unknown store is an error; republish observes nothing; the workflow takes its list from `node --import tsx scripts/observed-stores.ts` and contains no `.observation.cadence` read of its own; every store not observed gets `--republish`; the test file passes.
- C3: The pipeline and the `crawl` command refuse to observe a stopped store, and republish still works. Verify: read `assertObserved` and its two call sites (`src/pipeline/run.ts`, `src/cli/main.ts`); run `npx vitest run tests/integration/pipeline.test.ts`; run `node --import tsx src/cli/main.ts crawl --config config/ksy.json --out <a temp dir>` with a 30 s timeout. Expect: crawl, `--snapshot` and `--bootstrap` runs of a stopped store fail with exit 1 before any stage runs and send no request; `--republish` exits 0 with the run count unchanged; the CLI prints `ksy is no longer observed ...`, exits 1 within a few seconds, and creates no file in the temp dir.
- C4: A stopped store's dataset claims no sampling interval, keeps its observation window, and the published contract shape is unchanged. Verify: read `SAMPLING_CAVEAT` / `storeLevelCaveats` and the `samplingIntervalDays` line in `src/publisher/generate.ts`, `CAVEAT_KEYS` and `CONTRACT_VERSION` in `src/publisher/contract.ts` (compare with `git diff main -- src/publisher/contract.ts`); run `npx vitest run tests/contract/publisher.test.ts`. Expect: `stopped` maps to no caveat and gets no `samplingIntervalDays`; the cadence→caveat table is a `Record<ObservationCadence, …>` (exhaustive); no caveat key added and `CONTRACT_VERSION` unchanged; tests pass.
- C5: The whole repository still checks. Verify: `npm run typecheck`; `npm test`; `npm run matching:check`; the CI guard from `.github/workflows/ci.yml` step "Common core must not name a store" (run its grep); `git grep -nIE 'C:[\\/]+Users[\\/]+[A-Za-z0-9._~-]' -- .` after `git add -N scripts/observed-stores.ts`. Expect: typecheck exit 0; all test files pass (at least 59 files, 801 tests); matching check exit 0; both guards print nothing.
- C6: The new tests fail without the change they pin. Verify: one at a time, apply each mutation, run `npx vitest run tests/integration/observation-cadence.test.ts tests/integration/pipeline.test.ts tests/contract/publisher.test.ts`, then restore the file exactly (`git diff --stat` must match the starting state): (a) delete the line `if (options.republish !== true) assertObserved(config);` in `src/pipeline/run.ts`; (b) change `stopped: null,` to `stopped: 'sampling_interval',` in `src/publisher/generate.ts`; (c) in `scripts/observed-stores.ts` replace `return input.stores.filter((store) => input.cadenceOf(store) !== 'stopped');` with `return [...input.stores];`. Expect: each mutation makes at least one test fail; after restoring, the three files pass again.
- C7: Decision and operations are documented accurately. Verify: read `docs/adr/0029-stopped-store-observation.md`, its row in `docs/adr/README.md`, the 「定期 run」 and 「頻度を変える / 止める」 sections of `docs/runbook.md`, the KSY mentions in `README.md` and `CLAUDE.md`, the 「データについて」 note in `public/index.html` (deployed to Pages); run `git grep -n "6店舗とも\|両店舗を順次" -- README.md docs/runbook.md public/index.html`; check each factual claim against the code (selection rules, refusal paths, exit code 1, caveat/`samplingIntervalDays` behaviour, the comparison card's 「最終観測」 line in `userscript/ui/related.ts`, the 「観測期間」 line in `userscript/ui/panel.ts`, KSY relation counts via `node --import tsx -e "import('./userscript/adapters/productRelations.ts').then(m=>{const r=m.PRODUCT_RELATIONS;console.log(r.length,r.filter(x=>x.products.some(p=>p.storeId==='ksy')).length,r.filter(x=>x.pricePolicy&&x.products.some(p=>p.storeId==='ksy')).length)})"`). Expect: no claim contradicts the code; the ADR states what was decided, why, and what is out of scope; the grep prints nothing, and no current-state statement in README, the runbook or the landing page says all six stores are observed every two days or that KSY's dataset carries `samplingIntervalDays: 2` (historical release notes and verification records may keep what was true then).
