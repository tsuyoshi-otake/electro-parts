# Goal: Observe every still-observed store once a day instead of every second day (Issue #82)
Workdir: C:\Codes\tsuyoshi-otake\electro-parts (branch feat/daily-observation, uncommitted working tree against main)

Context for the verifier: `config/<store>.json` `observation.cadence` used to be `every_two_days` for five stores and `stopped` for ksy. The workflow had a gate job (`schedule`) that let `crawl` run only on every second day. The task replaces that with `daily`: no gate, one cron, the stock-count rotation advancing one slice per day, the manifest claiming `samplingIntervalDays: 1`, and the client showing "おおむね1日に1回". Old clients must keep working (no new caveat key may be emitted).

## Criteria
- C1: The old cadence and its gate are gone from code, config, workflow and tests. Verify: `grep -rnE "every_two_days|EVERY_TWO_DAYS|observation-schedule|observationDue|observationRound|everyTwoDays" src scripts userscript tests .github config extension | grep -v "sampling_interval_every_two_days"`; `test ! -e scripts/observation-schedule.ts`. Expect: the only line printed is the guard `expect(workflow).not.toContain('observation-schedule')` in tests/integration/observation-cadence.test.ts; the file does not exist. (The caveat KEY `sampling_interval_every_two_days` is allowed to remain: it is never emitted, only worded by the client for data cached from the two-day period.)
- C2: Store configs. Verify: for each `config/*.json` print `storeId` and `observation.cadence` (e.g. `node -e "for (const f of require('fs').readdirSync('config')) if (f.endsWith('.json')) { const c = JSON.parse(require('fs').readFileSync('config/'+f,'utf8')); console.log(f, c.observation && c.observation.cadence) }"`). Expect: akizuki, m5stack, pimoroni, sengoku, switch-science are `daily`; ksy is `stopped`; no other value appears.
- C3: Workflow structure. Verify: read `.github/workflows/crawl-publish.yml`. Expect: exactly one `- cron: '0 20 * * *'`; the top-level `env:` has `DAILY_CRON: '0 20 * * *'` and no `EVERY_TWO_DAYS_CRON`; the `jobs:` mapping has no `schedule` job (list the two-space-indented keys under `jobs:`); `crawl` has no `needs:` and no job-level `if:`; every remaining `needs:` is `needs: crawl` (or a list containing only existing jobs); the `deploy` job still depends on `crawl`; the YAML is well formed (consistent 2-space indentation under `jobs:`, no dangling keys left from the removed job).
- C4: The selection script serves the daily schedule from the real configs. Verify: `STORES="akizuki switch-science m5stack ksy sengoku pimoroni" DAILY_CRON='0 20 * * *' EVENT_NAME=schedule EVENT_CRON='0 20 * * *' OBSERVE= REPUBLISH=false node --import tsx scripts/observed-stores.ts; echo "exit=$?"`; repeat with `EVENT_CRON='0 21 * * *'`; repeat with `EVENT_NAME=workflow_dispatch EVENT_CRON= OBSERVE=ksy`. Expect: first prints `akizuki switch-science m5stack sengoku pimoroni` and exit=0; second prints nothing on stdout, `::error::unknown schedule '0 21 * * *'` on stderr and exit=1; third prints `::error::store 'ksy' is no longer observed ...` and exit=1.
- C5: The published claim follows the cadence from one table. Verify: read `src/publisher/generate.ts` (`SAMPLING`) and run `npx vitest run tests/contract/publisher.test.ts`. Expect: `Record<ObservationCadence, ...>` exhaustively lists daily/weekly/monthly/stopped; daily yields `samplingIntervalDays: 1` and no sampling caveat key; weekly and monthly keep `sampling_interval_weekly` / `sampling_interval`; stopped yields no interval and no key; `CAVEAT_KEYS` emitted by the generator never contains `sampling_interval_daily`; tests pass.
- C6: The stock-count rotation advances one slice per day. Verify: read `src/collectors/productPageInventory.ts` (uses `observationDayCount`), `src/core/observationDay.ts`; run `npx vitest run tests/unit/product-page-inventory.test.ts`. Expect: consecutive days select consecutive `shard` values (0,1,2,3,0,...), `round` equals the day count, `shards` in `config/switch-science.json` and `config/m5stack.json` is unchanged from `git show main:config/<store>.json`, tests pass.
- C7: The client words the daily interval and still reads the old one. Verify: read `userscript/core/format.ts` and `userscript/ui/panel.ts` (`manifestCaveats`); run `npx vitest run tests/userscript/controller-panel.test.ts`. Expect: `samplingIntervalDays === 1` shows `おおむね1日に1回`, `=== 2` still shows `おおむね2日に1回`, neither requires a caveat key in the manifest; tests pass.
- C8: Version 0.7.7 everywhere it is declared. Verify: `grep -n "0\.7\.7" package.json userscript/version.ts`, `node -e "const l=require('./package-lock.json'); console.log(l.version, l.packages[''].version)"`, and `git diff main -- package.json package-lock.json userscript/version.ts`. Expect: all three read 0.7.7 and the only version-related changes in those files are 0.7.6 → 0.7.7.
- C9: Whole-repo gates. Verify: `npm run typecheck; echo exit=$?`, then `npm test; echo exit=$?` (a few minutes; wait for it). Expect: both exit 0; no skipped-by-edit tests (compare `git diff --stat main -- tests` to confirm only the intended tests changed: observation-cadence, product-page-inventory, publisher, controller-panel).
- C10: The changed tests really guard the behaviour (fail-before). Verify, in a throwaway copy of the repo (`cp -r` to a new directory under the scratchpad, excluding node_modules but symlinking/junction-ing it is fine; never modify the Workdir): (a) in the copy set `config/akizuki.json` cadence back to `every_two_days` and run `npx vitest run tests/integration/observation-cadence.test.ts`; (b) in the copy change `intervalDays: 1` to `intervalDays: 2` in `src/publisher/generate.ts` and run `npx vitest run tests/contract/publisher.test.ts`; (c) in the copy change `observationDayCount(o.observedAtMs)` to `Math.floor(observationDayCount(o.observedAtMs) / 2)` in `src/collectors/productPageInventory.ts` and run `npx vitest run tests/unit/product-page-inventory.test.ts`. Expect: ADR-0030 exists with 決定/負荷/影響; the README row exists; every remaining grep match is clearly past tense or historical release-note text (a present-tense claim that observation is every two days is a fail); the run's wall time is about 2 h 55 min, matching the ADR's figure.
- C12: Nothing else changed. Verify: `git status --short` and `git diff --stat main`. Expect: no changes outside the files implied by C1–C11 (config/*.json, .github/workflows/crawl-publish.yml, scripts/observed-stores.ts, scripts/observation-schedule.ts removed, src/{core/observationDay,collectors/productPageInventory,adapters/productPageInventory,pipeline/config,publisher/contract,publisher/generate}.ts, userscript/{core/format,ui/panel,version}.ts, package*.json, the four test files, README.md, docs/**, public/index.html, this rubric); no stray temp files; no secrets.
