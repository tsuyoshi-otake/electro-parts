# Goal: `npm run cws:dashboard -- fill` puts each field, reads every field back from a fresh tab, repeats what did not stick (bounded) and reports what never sticks (Issue #89)
Workdir: C:\Codes\tsuyoshi-otake\electro-parts (branch fix/cws-fill-readback-089, one commit on top of main)

Context for the verifier: during the 0.7.8 submission `fill` printed `saved` for both tabs, yet two privacy fields stayed on the old text. The dashboard autosaves when a field loses focus and disables its 「下書きとして保存する」 button while it saves. The change: `scripts/lib/fill-until-kept.ts` (`fillUntilKept`, the dashboard-free retry policy: read every field, put those not kept, read all back, up to `FILL_ROUNDS` = 3 rounds, return what is still not kept) and `scripts/cws-dashboard.ts` (`putField` per field with a save that waits for the enabled button, `holdsText` reading from a freshly loaded tab, `fill` returning the labels not kept, `check` returning the number that differ, `main` setting exit code 1). `tests/e2e/cws-dashboard-fill.spec.ts` runs `fill` and `check` against a stand-in dashboard served by route interception. The stand-in models an inferred failure, not the real dashboard; the real one has not been run (the owner signs in at the next submission). The ZIP, the extension and the data are not part of this change.

Rules for you: do not edit anything in the Workdir.
