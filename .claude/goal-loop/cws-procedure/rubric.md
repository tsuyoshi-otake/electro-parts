# Goal: the Chrome Web Store dashboard transcription is a repeatable, tested script that never submits, and the procedure is documented where the next submission starts
Workdir: C:\Codes\tsuyoshi-otake\electro-parts (Git Bash; branch main, uncommitted working tree)

Run each command from the workdir. Read exit codes from the command itself (`cmd; echo EXIT=$?`), never through a pipe. Do not run the `launch`, `upload`, `fill`, `blockers` or `close` commands of the script: they change the dashboard or the browser.

## Criteria

- C1: Types pass. Verify: `npm run typecheck; echo EXIT=$?`. Expect: EXIT=0.
- C2: The listing reader is tested against the real document. Verify: `timeout 300 npx vitest run tests/contract/chrome-web-store.test.ts > /tmp/c2.log 2>&1; echo EXIT=$?; grep -E "Test Files|Tests |✓|×" /tmp/c2.log | head -30`; then read `tests/contract/chrome-web-store.test.ts` (describe 'Chrome Web Store dashboard texts') and `scripts/lib/store-listing.ts`. Expect: EXIT=0, 0 failed; the describe has a test that checks all four texts within 16,000 / 1,000 code points, one that checks every content-script host appears in both the description and the host reason, and one that expects a throw for a missing heading and a missing storage row.
- C3: The script cannot submit or publish. Verify: read `scripts/cws-dashboard.ts`; `grep -n "click\|press(" scripts/cws-dashboard.ts`; `grep -n "審査のため送信\|'公開'\|\"公開\"" scripts/cws-dashboard.ts`. Expect: the only element click is inside `press()`, which throws for any label outside `PRESSABLE`; `PRESSABLE` holds exactly 下書きとして保存する, 送信できない理由, 新しいパッケージをアップロード; 審査のため送信 and 公開 appear only in comments; dialogs are closed with `keyboard.press('Escape')`, not by a button label.
- C4: No dashboard publisher id or other personal identifier is added. Verify: `git diff HEAD -- . ':!.claude/memory' | grep -nE "[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}"; echo EXIT=$?` and `grep -nE "[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}|@[a-z0-9.-]+\.(jp|com)" scripts/cws-dashboard.ts scripts/lib/store-listing.ts; echo EXIT=$?`. Expect: both EXIT=1 (no match); the publisher id is read at runtime from the dashboard URL.
- C5: The procedure is documented where the next submission starts. Verify: `grep -n "cws:dashboard" package.json docs/chrome-web-store-listing.md docs/runbook.md CLAUDE.md` and read the section 「提出と、落ちたときの読み方」 of `docs/chrome-web-store-listing.md`. Expect: package.json maps `cws:dashboard` to `node --import tsx scripts/cws-dashboard.ts`; the doc lists, in order, launch, the person signing in, status, upload, fill, check, blockers, the person pressing 「審査のため送信」, close; it says why (extensions cannot script the dashboard; the default profile ignores the debugging port) and that the script never submits; runbook and CLAUDE.md point to it and say the person presses 「審査のため送信」.
- C6: The read-only commands work on the live dashboard. Verify: `curl -s --max-time 3 http://127.0.0.1:9333/json/version | head -2`, then `timeout 200 npm run -s cws:dashboard -- status; echo EXIT=$?` and `timeout 200 npm run -s cws:dashboard -- check; echo EXIT=$?`. Expect: a Chrome answers on 9333; status prints `ステータス: 審査待ち`, `ドラフト: 0.5.1`, `公開済み: 0.4.9`; check prints `same` for 説明, 単一用途の説明, storage が必要な理由, ホスト権限 が必要な理由; both EXIT=0.
