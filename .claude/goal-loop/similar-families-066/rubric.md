# Goal: 型番のある商品どうしの類似商品探索（0.6.6, Issue #50）を、既存の照合を変えずに全件判定済みで出す
Workdir: リポジトリのルート
Baseline: 0.6.5 の `data/matching`（0.6.6 の変更を入れる前の状態）。0.6.4〜0.6.6 を同じブランチで作ったため、採点時は作業用の一時コピーを使う（場所は採点の依頼で渡す）。

## Criteria
- C1: 生成物が正本から再現でき、未判定の候補がない。Verify: `npm run matching:check --silent`。Expect: 終了コード0、出力に `"candidates":4176,"pending":0,"relations":5095` と `"similar":1031` を含む。
- C2: 未判定の類似商品の提案がない。Verify: `npm run matching:similar --silent` の出力行数と、`data/matching/coverage.json` の `similarProposals`・`dismissedLeads`。Expect: 0行、`similarProposals` は空配列、`dismissedLeads` は `{"different":33,"identity":13}`。
- C3: 既存の候補・レビュー・aliasを変えていない。Verify: baseline の `candidates.jsonl`・`reviews.json`・`aliases.json` と、現行の `data/matching/` の同名ファイルをバイト単位で比べる（例: `cmp`）。Expect: 3ファイルとも一致。
- C4: 新しい製品群が類似商品の規則を満たす。Verify: `data/matching/families.json` で `id` が `stem-` で始まる製品群を調べ、`data/matching/catalog.jsonl` の行（`storeId/pageKey` がメンバーの `key`）と突き合わせる。Expect: 41件、メンバー計191行。各製品群は2店舗以上の行を含む。製品群の中で特徴のキーの集合は全メンバーで同じ。同じ `variant` のメンバーは特徴の値もすべて同じ。違う店舗で `variant` が違うメンバーの組は、少なくとも1つの特徴の値が違う。特徴の値に `記載なし`・`不明`・`未記載` を含まない。カタログで `variants` を持つ行のメンバーには `offerId` があり、その行の `variants` に同じ `offerId` がある。`coverage.json` の `familyCounts` で `stem-` の値はすべて1以上、合計190。
- C5: 除外の記録が自然言語の判定の形を満たし、同一の可能性の組を類似商品にしていない。Verify: `data/matching/dismissals.json` を読み、`userscript/adapters/productRelations.ts` か `npx tsx` での生成結果と突き合わせる。Expect: 46件（`different` 33、`identity` 13）。全件の `evidence` が `類似候補（共通語幹:` で始まる。`reviewerModel` は `Claude Sonnet 5.5` か `Claude Opus 5.5`。Opus のものは20件で、すべて `evidence` に `初回判定（Claude Sonnet 5.5）は` を含む。どの除外の2行の組にも、生成された関係（同一・類似・要確認）がない。
- C6: 初回判定と標本が残っている。Verify: `.claude/goal-loop/similar-families-066/` を読む。Expect: `sonnet-groups.json` は53グループで、各グループに `group`・`families`・`dismissed` がある。`leads.jsonl` は234行。`precision-sample.jsonl` は90行で、`verdict` の内訳が similar 42・different 39・same 6・unknown 3。`opus-overrides.json` はグループ1を含む。このフォルダと、変更した `docs/`・`README.md`・`public/index.html` に、ローカルのユーザーパス（`C:\Users`、`DEVELO~1`、`AppData`）を含まない。
- C7: 探索が有界で、テストと型検査が通る。Verify: `scripts/matching/names.ts` を読み、`npx vitest run tests/unit/matching-names.test.ts tests/unit/matching-generator.test.ts` と `npm run typecheck` を実行する。Expect: `proposeSimilar` に計算量の記述があり、全行×全行の二重ループがない。テストは全件成功し、20,000行×2店舗のテストを含む。typecheck は終了コード0。
- C8: 版と記録が更新されている。Verify: `package.json`・`package-lock.json`（ルートの2か所）・`userscript/version.ts` の版を読む。`docs/adr/0018-reviewed-catalog-mapping-pipeline.md`、`docs/roadmap/three-store-mapping.md`、`README.md`、`public/index.html` を読む。Expect: 版はすべて0.6.6。ADR に `## 0.6.6` があり、その下に `### 範囲の測定`、`### 提案の規則`、`### 判定の記録`、`### 判定の手順と統合確認`、`### 結果` がある。ADR の更新手順の3に `npm run matching:similar` がある。照合レポートの0.6.6の表の「計」行は234・188・33・13・190で、各店舗の組の行の列ごとの合計と一致する。README と index.html は0.6.6と5,095組を記載する。
- C9: 共通コアに店舗名を足しておらず、同一商品でつながる行の間に矛盾が増えていない。Verify: `git status --short` で変更ファイルを列挙する。`node .claude/goal-loop/name-discovery-065/consistency.mjs .` を実行する。Expect: `src/core`、`src/db`、`src/publisher`、`src/pipeline`、`userscript/core`、`userscript/ui` の下に変更ファイルがない。`conflicts` は `a116956-s5843 unresolved` と `a130198-s5682 unresolved` の2件だけ。
