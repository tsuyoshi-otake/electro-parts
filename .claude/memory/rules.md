# Rules (distilled, verified)

- **Akizuki WAF rejects User-Agents containing the word `crawler` with 403.** A descriptive project UA with a contact URL (`electro-parts-price-history/0.1 (+https://github.com/...; research)`) is accepted. Never fake a browser UA; if refused, stop.
- **`curl.exe` on this box segfaults on some HTTPS hosts.** Use `node -e "fetch(...)"` for live probes instead.
- **Bash heredocs in this harness mangle content**: `\\0` becomes a NUL byte, `\\01` an octal escape, and non-ASCII (Japanese) can arrive as broken bytes; long heredocs with many quotes fail with "unexpected EOF while looking for matching `''". Write whole files with the Write tool (or a Python script written with Write, then executed). Patch bytes with `python -c` using `chr()`.
- **The Edit tool interprets `\u0000` in `old_string`.** Use `String.fromCharCode(0)` in source and avoid escape sequences in the match text.
- **Bash cwd resets on every call.** Always `cd "C:\Codes\tsuyoshi-otake\electro-parts"` first (the worktree path is only a pointer for this session).
- **`basisKey` joins fields with `\u0000` and encodes a null `unitLabel` as `\u0001`.** Tests must build expected keys with `String.fromCharCode`.
- **`npm run pipeline -- summary` is wrong**: the script already contains `pipeline`. Use `node --import tsx src/cli/main.ts summary --report ...`.
- **Sanity thresholds are strict `>`.** A drop of exactly the threshold is not quarantined; tests must use the boundary in both directions.
- **Stryker with `vitest.related: true` produced 100 NoCoverage mutants (68.95 %)**; `related: false, dir: 'tests'` plus targeted guard tests gives 89.60 %. Keep `related: false`.
- **Buffer → ArrayBuffer**: slice with `buf.buffer.slice(buf.byteOffset, buf.byteOffset + buf.byteLength)`; a pooled Buffer's `.buffer` is larger than the data.
- **jsdom fixtures**: building test DOMs with `innerHTML` is fine in tests, but the production bundle must never contain HTML-string sinks (CI greps the bundle).
- **Playwright needs `npx playwright install chromium`** once per machine; in CI `--with-deps`.
- **After test / bench runs, verify processes exited** (`Get-CimInstance Win32_Process` filtered on the command line). Long benches run for 30+ min; do not block on them.
- **Full 9,000-product daily benchmark takes ~3 min (1 y), ~10 min (3 y), ~20 min (5 y) of import time.** Run it in the background and write results to a file outside the repo.
- **Size a background benchmark’s `timeout` from the largest row.** The 5-year / 9,000-product row alone needs ~20 min of import time; a shared timeout killed the run (exit 124) after the 3-year row. Print each row to stderr as it completes so a kill does not lose finished work.
- **Akizuki's `.block-goods-detail` is a CSS grid (420 px + 660 px) whose panes pin their own `grid-row`.** Anything inserted as a sibling is auto-placed: 420 px wide, in a new row below every pane. Mount inside `.pane-goods-center` (a plain 1080 px block) instead; a fallback that must land in the grid needs `grid-column: 1 / -1`.
- **Never compare listing occurrences by their display strings.** The spec-table layout prints every price as `￥N～` where the card layout prints `￥N`; comparing text reported 221 real products as disagreeing every run. Compare what is recorded (amount, tax flag, unit, stock status).
- **A validator must not demand a field the normalizer ignores.** Requiring 税込 on a 販売終了 cell (`amountYen: null`) quarantined a complete 12,772-item snapshot over a field no code reads. Cost: one full 85-minute crawl.
- **Playwright's `outputDir` wipes `test-results/` at the start of every run.** Keep one-off live-check scripts under `reports/` (also gitignored) or they vanish mid-session.
- **Coverage claims need an oracle.** Akizuki publishes `Sitemap_index.xml` (13,027 products, 458 `c`, 1,412 `r`); crawl families are fixed at `c + r` (98.04 %) and must never alternate, or `coverageId` churns and single-family products get fake delisted/relisted history.
- **Changing the crawl cadence touches more than cron**: the user-visible sampling caveat lives in `userscript/core/format.ts`, and snapshot artifact retention must exceed the crawl interval (30 days was shorter than a month).

  - Since ADR-0016 the cadence is declared per store in `config/<store>.json` (`observation.cadence`) and the workflow derives both the observed stores and the caveat from it. **Never write a store name next to a cron**; change the config instead. Raising a cadence is judged by the load on the store, not by size — weekly costs 4.33x the runs but only 1.23x the published bytes.
- **A userscript fix is not shipped until `@version` is bumped.** Tampermonkey only re-fetches `@updateURL` when the advertised version is higher, so a deployed-but-unversioned bundle reaches Pages and never reaches an installed browser. Byte-comparing the published file against the local build does not catch this — it verifies publication, not delivery. Bump `userscript/version.ts` in the same commit as any change to the bundle.

- **The published `site/` tree is replaced whole, so every store must be regenerated in every run.** Two stores share one SQLite history, one `state/` and one `site/`: run them serially with the second chained via `--previous-dir site/state` (from the same previous state, the last `finalizeDatabase` discards the other run), regenerate unselected or failed stores with `--republish`, and gate the deploy on every expected manifest being present. A store that writes nothing in a run disappears from Pages.
- **`$TMPDIR` is unset under Git Bash here.** `--out "$TMPDIR/x"` resolves to `C:\Program Files\Git\x` and fails on mkdir. Pass the scratchpad path explicitly.
- **No YAML parser is installed** (no PyYAML, no `yaml`/`js-yaml`). Validate workflows with `~/tmp/actionlint-1.7.12-win/actionlint.exe .github/workflows/*.yml` instead of building a venv to parse one file.
- **`(await res.text()).length` is UTF-16 code units, not bytes.** The userscript bundle carries Japanese strings, so this under-reports its size by ~1,200 and makes the published file look smaller than the local build. Compare with `Buffer.from(await res.arrayBuffer())` and `buf.equals(local)`.
- **A push to `main` never deploys.** Pages is written only by the `Crawl and publish` workflow; CI runs typecheck/tests/mutation and nothing else. "Green on main" is not "released" -- check `state/state.json`, the store manifest and the served `@version` on the live site before saying a change shipped.
- **Cross-store identity is not price eligibility.** Keep revision suffixes and packaging evidence; the old Shopify catalogue's manufacturer code and the current published model/SKU can differ. Explicitly check both product metadata and sales conditions. A single variant or `prices.minYen` does not prove a one-piece pack (ADR-0017).
- **Parallel product loads can multiply failed manifests.** Share both product and per-store manifest work, and make a failed manifest terminal for the page client. Queued candidates must not reissue it, and rendering/theme changes must never own fetching. Tests pin the two-request bound, deduplication and 429 finalization.
- **Manufacturer codes can collide even when they are numeric or look distinctive.** The full saved-catalogue scan found ten unrelated numeric-code pairs and a Pi 5 SC1110 title/capacity contradiction. Keep SKU separate, review names/manufacturer/revision/configuration, and preserve unresolved outcomes over automatic family expansion. Reproduce with `tests/unit/matching-generator.test.ts`; generated mappings are not an editable source.
- **Variant mappings need offer IDs in serialized endpoint keys.** A page key alone overwrites different lengths/configurations sharing one page. Bind the reviewed offer ID and SKU, reject a different variant even on the same page, and never fall back after it changes. Verified by matching-generator/relations tests and the official LED-strip 20cm to 10cm live ZIP check (0.4.5).
- **Check every store-listing claim against the code that renders it, not against the previous listing.** The 0.5.1 description already claimed 「在庫表示の変化」 and a rewrite inherited it as 「在庫の推移グラフ」; the panel shows only the latest stock. Verified by: the independent verifier failed C3 on it and passed after the claims were cut to what `userscript/ui/` renders (#44).
- **Before mounting beside a shop's purchase column, learn how that column is positioned at each breakpoint.** M5Stack's `.product-info` is absolute (fixed while scrolling) at ≥1024 px but `float: left` in a zero-height wrapper below it, so a panel inserted after it is covered unless the host has `clear: both`. Text flows around a float; a block does not. Measure panel/column overlap while scrolling at 1440, 1024 and 390 px, not from one screenshot at the top. Verified by: 25 overlapping steps at 390 px before `clear: both`, 0 after (#42).
- **Viewport width is not embedding width.** A 390px panel inside a wide desktop page kept the two-column grid and crushed the chart. `.eph` now owns an inline-size container query; verify both narrow viewport and wide viewport/narrow parent, including chart width and horizontal overflow.
- **Stryker preprocesses non-mutated TypeScript too.** Its default `@ts-nocheck` insertion changed the generated mapping table inside the sandbox and broke the byte-exact assertion before mutation started. Limit `disableTypeChecks` to `src/**/*.ts`; keep the assertion strict. The corrected local dry run passed all 398 tests with no runner survivors.

- **Playwright loads an unpacked MV3 extension only via `chromium.launchPersistentContext(dir, { channel: 'chromium', args: ['--disable-extensions-except=...', '--load-extension=...'] })`** - the bundled build and `chromium.launch` do not load extensions. `context.route` *does* intercept the service worker's own fetches, so the request bound is testable for the extension too. Remove the temp profile in `finally`.
- **A tsconfig must actually cover `extension/`, or `chrome.d.ts` is never loaded** and every `chrome.*` use is an unknown name. Three projects are typechecked: root, `userscript/`, `extension/`; the root one includes `extension/chrome.d.ts` so tests importing extension modules see the ambient namespace.
- **A jsdom mount test can pass while the panel is showing an error.** The akizuki adapter's `pageKey` is the numeric goods id (`109951`), not the URL segment (`g109951`); routing the fixture under the wrong key rendered "取得できませんでした" and the test still passed. Always assert a rendered value *and* the absence of the failure string.

- **Chrome ウェブストア never accepts the same version twice**, and an uploaded package may not carry `update_url` or `key`. Resubmitting means bumping `USERSCRIPT_VERSION` (which is also the extension version - same bundle, one number). The privacy policy URL must already resolve: publish Pages before submitting.
- **The panel's `section` is replaced when data arrives.** A Playwright locator resolved during loading detaches mid-action ("Element is not attached to the DOM"). Scroll and wait by the host element `#electronics-price-history-root`, which keeps its identity.
- **The chart is lazy (IntersectionObserver).** Waiting for the chart (`svg.eph-chart`) to be visible before scrolling the panel into view times out. Scroll first, then wait for the SVG.

- **Screenshots and demos: one throwaway browser profile per shot.** The extension caches manifests and products in `chrome.storage.local`, so a shared profile leaks one dataset's version into another shot and the panel renders `dataset version differs from manifest (publication in progress?)`.
- **The comparison chart's `svg` is `role="group"`; the single-store chart is `role="img"`.** Wait on `svg.eph-chart` when either may appear.
- **No mapped pair is capturable offline.** The checked-in switch-science snapshot is a 60-product sample and shares no relation with the akizuki snapshot, and only 2 of 424 relations carry a `pricePolicy` (ATOM Lite, Arduino UNO R4 Minima). Showing a real cross-store comparison means reading the published dataset - never synthesising one for an image a user will see.
- **A generated image is not verified until it has been looked at.** All three screenshot defects (wrong wait selector, cache bleed, visible spinner) exited 0.

- **Chrome ウェブストアのギャラリー(`chrome.google.com/webstore/*`)は拡張からのスクリプト実行もスクリーンショットも禁止**
  (`The extensions gallery cannot be scripted`)。claude-in-chrome も computer-use(ブラウザは tier "read")も使えない。
  ダッシュボードを自動操作する唯一の経路は**外部 CDP** - Playwright の `connectOverCDP` は拡張ではないので通る。
- **Chrome 136 以降は既定の user-data-dir では `--remote-debugging-port` を無視する。** フラグが付いていても 9222 は listen しない。
  `--user-data-dir` に別ディレクトリを渡した Chrome を新しく起動し、本人にログインしてもらう。署名済みプロファイルの複製はしない。
- **Google の Material UI では Playwright の `.click()` が overlay に奪われる**(`div.VfPpkd-aPP78e`、`div[jsname="GGAcbc"]`、
  開いたままのダイアログ)。`page.evaluate` から DOM の `.click()` を呼ぶ。ネイティブ input のラジオ/チェックボックスもこれで change が出る。
- **ストアのアイテム名と概要はダッシュボードで編集できない**(アップロードした zip のマニフェストから読む)。
  文言を変えるにはパッケージを作り直して版を上げる。
- **掲載画像は 6 枚**: スクリーンショット 4(1280×800)、ショップアイコン 128×128、プロモーションタイル 440×280 と 1400×560。
  **JPEG か 24 ビット PNG のみ**(アルファ不可)。スクリーンショットの file input は `multiple` ではないので 1 枚ずつ設定する。
- **提出可否の根拠は「送信できない理由」ダイアログだけを見る。** Google が未入力欄を列挙する。全部埋めると本文が空になる。
- **ダッシュボードのダイアログは Escape で閉じ、ボタンは表示中の 1 つのダイアログ内だけで押す。** `[role=dialog] button` を文言(「OK」等)で全件押すと、非表示で描画済みのダイアログのボタンも押される。0.5.1 では「公開できません」を閉じるつもりの一括「OK」の直後に「アイテムを送信しています...」が出て、審査待ちになった(#36)。

- **Chrome 152 は `--load-extension` を完全に無視する。** 同じ `dist/extension` を Chromium 151 は読み込む
  (chrome://extensions に掲載され、service worker `.../background.js` が動く)のに、Chrome 152 は一覧が空。
  `--disable-features=DisableLoadExtensionCommandLineSwitch` でも戻らない。CDP の `Extensions.loadUnpacked` は
  **ブラウザ級ドメイン**なので `context.browser().newBrowserCDPSession()` が要る(ページ側の session では
  `Method not available`)。それは id を返して成功するが、Chrome 152 では拡張が不活性のまま
  (service worker なし、自分の manifest.json すら `ERR_BLOCKED_BY_CLIENT`、content script が動かない)。
  **実ブラウザでの拡張検証は `channel: 'chromium'` で行う。** インストール済み Chrome での最終確認は人手。
- **保存済みスナップショットを `context.route` で返す E2E は「実サイトで動作確認した」ことにはならない。**
  実データ・実 DOM・実 CSP のどれも通っていない。リリース前に一度は実ページで開く(1 ストア 1 ページで足りる)。
- **グラフの横はみ出し検査だけでは文字の可読性を確認できない。** 単店・比較それぞれで実幅/viewBox幅を確認し、初期の狭幅とリサイズ後を検証する。固定760px viewBoxは390px画面で11pxの軸文字を4.69pxに縮めた（0.4.6で修正）。

- **Content-script and `@match` path patterns are compared against path plus query, with `*` the only wildcard (`?` is literal).** `https://host/` matches only the bare root; the home page with a query needs `https://host/?*` too. Scope the theme by a browsing-path allowlist in `matchPatterns` (the single source for manifest, `@match` and the controller), never by site-wide `/*` plus in-code exclusions. Verified by: `tests/e2e/page-theme-scope.spec.ts` in real Chromium (`/` and `/?ref=x` themed; cart/checkout/account untouched) and `tests/userscript/page-scope.test.ts` (#27).
- **The `<html data-eph-owner>` claim lives on the shared jsdom document across tests.** Remove it (and `data-eph-page-theme`, theme styles) in `afterEach`, and simulate a reload with the previous handle's `destroy()`, not by removing the panel host - otherwise the next mount yields with `another instance owns this page`. Verified by: three controller-panel tests that failed until switched to `destroy()` (#27).
- **A public API that answers `access-control-allow-origin: *` needs no `host_permissions`.** The MV3 worker reads it with `credentials: 'omit'`; keep the worker allowlist to the exact URL (`isAllowedFetchUrl`) and add only `@connect` for the userscript. Third-party rates whose terms forbid redistribution are fetched per browser, never published through the dataset. Verified by: 0.4.8 ZIP in local Chromium with host permissions = dataset origin only, real `open.er-api.com` fetch stored and shown on the live M5Stack page (#28).
- **Live checks: read panel text from the shadow `<section>`, not the host.** Playwright `innerText()` on `#electronics-price-history-root` returns `""` because the content is in its shadow root. Every chart (single-store too) is drawn lazily when its `.chart-box` enters the viewport, so wait for the series checkbox or the `svg` after scrolling instead of counting at once. Scroll the `.chart-box` itself into view, not the host: a panel taller than the viewport is centred by `scrollIntoViewIfNeeded()`, which can leave the chart box above the viewport and undrawn, and an element screenshot does not scroll it in (SS 9809, #36). Reuse the first run's profile for reruns so stored data (theme, exchange rate) serves them without new third-party requests. Verified by: the first 0.4.8 live run failed on these, the fixed reruns passed (#28).
- **Known store-side exceptions, not ours:** Switch Science `empire.js` `_updatePrice` (`Cannot read properties of null (reading 'innerHTML')`) and M5Stack `Goaffpro is already loaded` also occur in a fresh profile without the extension. Verified by: with/without-extension comparison on 2026-10-04 (#28).
- **Live checks: select relation cards by `[data-relation-id]` and wait for async parts.** Same-product cards are `.store-price`, other relations `.related-card`; both carry `data-relation-id`. The M5Stack yen line (`.fx-value`) renders after the panel, so wait for it before screenshots. A card holds two links to the same product and its own evidence `<summary>`, so select a link by `[data-focus-key="product-<id>"]` and a group's summary by `summary[data-focus-key="group-<kind>"]`. Relation cards appear only when the viewed product has its own history; a page that shows 「記録なし」 shows no cards, so an E2E for cards must serve a history for the viewed product. Verified by: the first 0.4.9 live run failed on both; the fixed run passed 26/26 (#30). The 0.6.1 E2E failed without a 5LAU history and on two Akizuki links, and the live C08 on the nested summary; all passed after the selector and fixture fixes (#39).
- **TKW from Git Bash takes a Windows executable path.** Pass `"$(cygpath -w "$(command -v node)")"`; a POSIX path such as `/c/Program Files/nodejs/node` fails with `os error 2` before the target starts. Verified by: the 0.4.9 live check (#30).
- **Every release adds a `<h2>X.Y.Z: …</h2>` changelog entry to `public/index.html`, data-only releases included.** Put `grep -n "<h2>X.Y.Z" public/index.html` in the release rubric. Verified by: 0.4.9 shipped to Pages without it and needed a follow-up republish (#30).
- **A rubric or script that pipes a runner into `tail`/`grep` must read `${PIPESTATUS[0]}`.** Git Bash runs without `pipefail`, so `cmd | tail; echo $?` reports tail's status and a runner that prints a success summary but exits nonzero passes. Also write file-scope checks for the committed branch (rubric and journal included), not for the uncommitted state. Verified by: Codex review on PR #34 and the corrected C2/C6 commands (#33).
- **KSY's `remote_proxy.cfc` `product.list` pages by `offset` only.** `page` is silently ignored and returns the first page again; `max` accepts 11-59 only (out of range fills `failures`). Check the echoed `conditions.offset` and the constant `size` on every page. Verified by: the live probe and collection (16 pages, 776 = `size`) and the `fails closed: ignored pagination` / `offset echoed differently` tests (#32).
- **Never enumerate KSY product ids.** Products off the public list (`onlist: 0`) are readable by id and include customer-specific payment items carrying personal names. Collect the public list only, reject any item with `onlist !== 1`, and keep fixtures public-only. Verified by: the 2026-10-29 id probe (results deleted) and the `fails closed: hidden product` test (#32).
- **ColdFusion's JSON turns digit-only strings into numbers** (KSY `model` `4910066630270`). Convert back to text; leading zeros cannot be recovered. Verified by: the saved list fixture and the digit-only model test (#32).
- **A dialog that closes by `display: none` keeps its fields filled.** A page key read from the dialog's fields must also require the dialog to be shown, or the panel of a closed product stays. Verified by: the live check `KSY dialog closed: panel closed, light reset offered` and the adapter test that a closed dialog reads as no product (#32).
- **Screenshot a store dialog only after its open animation ends.** KSY fades the dialog in; an immediate shot shows ghosted images. Wait about 1.5 s. Verified by: ghosted then clean `ksy-*.png` in the live check (#32).
- **A header the store leaves transparent turns dark with the page.** When the page theme preserves a header (logos drawn for white), give it the background explicitly, not only via the preserve selector. Verified by: the KSY header going dark in the first live screenshot and staying white after `header { background-color: #fff }` (#32).
- **Before blaming a branch for `npm audit` failures, diff the lockfile against `main`.** Advisories published after the last `main` CI make every new PR fail the audit step. `diff <(git show main:package-lock.json) package-lock.json` showing only the version lines means the findings are not the branch's. Verified by: 9 findings (4 high) on #32 with a version-only lockfile diff; last `main` CI 2026-10-04 passed.
- **`gh pr merge --match-head-commit` takes the full 40-character SHA.** An abbreviated one fails with `Could not coerce value ... to GitObjectID`; read it from `gh pr view <n> --json headRefOid`. Verified by: the first #34 merge attempt failed, the full oid merged it (#33).
- **A generated TS array of object literals fails `typecheck` with TS2590 past ~1,300 rows.** TypeScript forms one union of every row's literal type. Emit each row through a typed helper (`r(relation, a, b): ProductRelation`) so each is checked on its own. Verified by: `productRelations.ts` at 1,356 rows failed, 1,032 passed, the helper version passes (#36).
- **Run E2E only as `npm run test:e2e` (or `npx playwright test -c tests/e2e/playwright.config.ts`).** A bare `npx playwright test` skips the global setup that builds `test-results/e2e-site` and wipes `test-results`, so specs fail with ENOENT for the saved site. Verified by: the failed bare run and the green rerun via the script (#36).
- **A store-scoped publish regenerates every store's manifest.** Compare `datasetVersion` and `productCount`, not whole files; `generatedAt` always moves. Verified by: the first KSY publish (run 40881517489), where the other three manifests differed only in `generatedAt` (#32).
- **A merge does not reach Pages by itself.** The daily scheduled run deploys only when some store is due (`Check observation day`); otherwise it skips both the crawl and the deploy, so a code release waits for the next due day. To ship it now, dispatch "Crawl and publish" with one due-or-cheap store and confirm the ZIP SHA256 and `@version` on Pages. Verified by: scheduled run 40975827202 on 689393e skipped both jobs and Pages kept 0.5.0 until the manual run 40983579127 (#36).
- **When a new store's first live crawl stops on an unknown format, save every page the collector reads once, politely, to a local cache, then finish the parser offline against it.** A fail-closed crawl stops at the first unknown format, so each further live attempt finds only one more format, and each one sends the store another batch of requests. Keep the cache local (it holds what the repository must not), replay the real collector through its injected transport, and delete the cache when done. Verified by: せんごく's first live run stopped at request 20 on 「在庫限り特価」; one cached pass of 548 requests let the offline replay find seven more shapes without another request (#39). Those shapes were: no-quantity lines, packs after quantity breaks, 価格お見積り with and without ¥0, a repeated basis, an empty price block, 【数量0個〜】, and a counter quirk on full last pages.
- **Read a store's price cell as the lines it shows, not as a quantity scale you expect.** せんごく's cell mixes quantity breaks, packs and reels (all 【数量1組〜】), so an "ascending quantity" check rejected about 680 real products. Keep lines in the shop's order, take the first as the price, and validate only the line syntax. Verified by: the shape count over the cached listings (#39).
- **Before calling a store's dark mode done, count low-contrast text on each kind of page the extension darkens.** Count visible elements whose own text has under 3:1 against the first opaque background behind them, then compare with the shop's own light colors. Screenshots of one product page miss side menus, headings and pale item boxes. A forced background on a "kept" header can also hide its own text. Verified by: せんごく's audit found 16 to 1,278 such elements per page; a white rule on the blue `.header_bar` had made its yellow greeting unreadable. After the fix, the only one left is a heading the shop itself draws at 2.3:1 (#39).
